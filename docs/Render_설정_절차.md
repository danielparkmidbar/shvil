# Render 설정 절차 — 다니엘 쌤이 직접 하시는 일

> 걸리는 시간: 약 10분 · 필요한 것: 컴퓨터, 인터넷, **종이 한 장과 펜**
> 이 문서만 보고 처음부터 끝까지 하실 수 있게 썼습니다. 어려운 말은 쓰지 않았습니다.

---

## 왜 이걸 하는가 (한 문단)

지금 서버는 **쉬는 동안 스스로 잠들고, 깨어날 때 자기 열쇠를 새로 만듭니다.**
열쇠가 바뀌면 이미 설치된 폰이 "이 서버가 아까 그 서버가 맞나?" 하고 의심해서
새 코스·새 목록을 더 이상 받지 않습니다. 실제로 어제 하루 동안 **세 번** 바뀌었습니다.

아래 절차는 열쇠를 **한 번 정해서 영원히 같게** 만듭니다.
그 열쇠의 씨앗이 되는 값이 아래에서 만들 **64글자 한 줄**입니다.

---

## 시작 전에 — 딱 하나만 확인해 주세요

**"지금 폰에 쉬빌 지갑이 깔려 있고, 그걸로 앱을 한 번이라도 열어 본 적이 있습니까?"**

- **아니오** → 그냥 아래를 하시면 됩니다. 아무 문제 없습니다.
- **예** → 그 폰은 이번 변경 뒤 "서버 열쇠가 바뀌었습니다"라고 알릴 수 있습니다.
  그 폰에 **코인이 들어 있다면 먼저 복구 문구를 종이에 적어 두시고**, 앱을 지웠다가
  새로 받은 앱으로 다시 까시면 됩니다.
  (지금 배포된 앱은 없습니다 — 인터넷에 올라간 설치 파일이 하나도 없는 것을 확인했습니다.
   그래서 이 질문은 다니엘 쌤 폰 하나에 대한 것입니다.)

## 1단계 — 열쇠의 씨앗 만들기 (컴퓨터에서 30초)

컴퓨터에서 이렇게 칩니다.

```
cd shvil-dev
node tools/시드생성.mjs
```

이런 모양이 나옵니다.

```
═══════════════════════════════════════════════════════════
 ① 이 한 줄이 시드입니다 — 종이에 적으세요
═══════════════════════════════════════════════════════════

  SHVIL_ROOT_SEED = 6fd6b844a1c2 ...(전부 64글자)

═══════════════════════════════════════════════════════════
 ② ★이 두 줄도 같은 종이에 적으세요 — 확인할 때 씁니다
═══════════════════════════════════════════════════════════

  배포 열쇠 이름 : distribution-11da251e8e04aadd3208cead5681a1ed
  배포 열쇠 지문 : 1E54 FF34 3C0A F70B
```

## 2단계 — 종이에 적기 (가장 중요합니다)

**세 줄을 모두 종이에 적으세요.**

| 적을 것 | 비밀입니까 | 무엇에 쓰나 |
|---|---|---|
| ① 64글자 한 줄 | ★**절대 비밀** | 서버에 넣는 값 |
| ② 배포 열쇠 이름 | 비밀 아님 | 제대로 들어갔는지 확인할 때 |
| ③ 배포 열쇠 지문 | 비밀 아님 | 폰이 물어볼 때 대답하는 값 |

### ①번에 대해서만 지킬 것

- **카톡·메일·사진·메모앱·스크린샷에 넣지 마세요.** 새어 나가면 누구나 쉬빌 코인을
  마음대로 만들 수 있습니다. 되돌릴 방법이 없습니다.
- **잃어버리면 되찾을 방법이 없습니다.** 이미 만들어진 코인은 그대로 살아 있지만,
  앞으로 만드는 코인과 앱 갱신이 기존 지갑에서 **영영 인정받지 못합니다.**
- 종이를 **두 장** 만들어 서로 다른 곳에 두시는 것을 권합니다(집·사무실 등).
  집이 물에 잠기거나 종이 한 장을 잃어도 화폐가 죽지 않게.

②③은 비밀이 아닙니다. 오히려 나중에 사람들에게 알려 줘야 하는 값입니다.

## 3단계 — Render 화면에 넣기 (5분)

1. 인터넷 주소창에 **`dashboard.render.com`** 을 칩니다. 로그인합니다.
2. 목록에서 **`shvil-directory`** 를 클릭합니다.
3. 왼쪽 메뉴에서 **`Environment`** 를 클릭합니다.
4. **`Add Environment Variable`** 단추를 누릅니다. 빈 칸 두 개가 생깁니다.
5. 왼쪽 칸(Key)에 정확히 이렇게 칩니다:

   ```
   SHVIL_ROOT_SEED
   ```

6. 오른쪽 칸(Value)에 **1단계의 64글자**를 붙여넣습니다.
   (앞뒤에 빈칸이 붙어도 알아서 무시됩니다. 대문자·소문자도 상관없습니다.)
7. 아래 **`Save Changes`** 를 누릅니다.
8. 저장하면 서버가 자동으로 다시 시작됩니다. **2~5분** 기다립니다.

### 3-B단계 (권합니다 · 1분 더) — 오타를 기계가 잡게 하기

64글자 중 **한 글자만 틀려도 서버는 아무 일 없다는 듯이 잘 뜹니다.**
틀린 값도 그냥 다른 열쇠가 될 뿐이기 때문입니다. 그래서 하나 더 넣습니다.

1. 다시 **`Add Environment Variable`**
2. 왼쪽 칸(Key):

   ```
   SHVIL_EXPECT_DIST_KEY_ID
   ```

3. 오른쪽 칸(Value): 종이의 **② 배포 열쇠 이름** (`distribution-` 으로 시작하는 줄)
4. **`Save Changes`**

이렇게 해 두면, 씨앗이 조금이라도 다르면 **서버가 아예 뜨지 않습니다.**
조용히 잘못되는 것보다 시끄럽게 안 되는 쪽이 안전합니다.
(이 값은 비밀이 아니므로 여기 넣어도 아무 위험이 없습니다.)

## 4단계 — 제대로 됐는지 확인 (1분)

인터넷 주소창에 이렇게 칩니다.

```
https://shvil-directory.onrender.com/health
```

(서버가 자고 있었으면 화면이 뜨는 데 30초쯤 걸립니다. 그건 정상입니다.)

### 이렇게 나오면 성공입니다

```
{"ok":true,"keySource":"SEED", ... ,
 "distKeyId":"distribution-11da251e8e04aadd3208cead5681a1ed",
 "distKeyFingerprint":"1E54 FF34 3C0A F70B", ... ,"warnings":[]}
```

★**보실 것은 딱 두 개입니다.**

- `distKeyId` 가 종이의 **② 배포 열쇠 이름**과 **같은가**
- `distKeyFingerprint` 가 종이의 **③ 배포 열쇠 지문**과 **같은가**

둘 다 같으면 끝났습니다.

> ⚠ `keySource: SEED` 와 `warnings: []` **만 보고 안심하시면 안 됩니다.**
> 씨앗을 잘못 붙여넣어도 그 두 개는 똑같이 나옵니다.
> **종이와 대조하는 것만이 진짜 확인입니다.**

### 이렇게 나오면 씨앗이 안 들어간 것입니다

```
{"keySource":"EPHEMERAL_RANDOM", ... ,"warnings":["★발행 키가 이 인스턴스 한정 무작위입니다 …"]}
```

→ 3단계 5번의 철자를 다시 보세요: `SHVIL_ROOT_SEED`

### 서버가 아예 안 뜨면 — 고장이 아닙니다

일부러 그렇게 만들었습니다. 씨앗 없이 뜨면 서버가 **조용히 새 열쇠를 만들어** 이번 사고가
그대로 반복되기 때문입니다. Render 화면의 **`Logs`** 를 누르면 한국어로 이유가 적혀 있습니다.

- "SHVIL_ROOT_SEED 환경변수가 없습니다" → 3단계를 다시.
- "배포 열쇠 이름이 예상과 다릅니다" → 씨앗을 붙여넣을 때 글자가 빠졌거나 더 붙었습니다.
  종이와 다시 대조해서 3단계 6번을 다시 하세요. (3-B단계를 하셨을 때만 나오는 안내입니다.)

## 5단계 — 폰이 "서버 열쇠가 바뀌었습니다"라고 하면

앱에서 **더보기 → 서버 열쇠 확인**을 누르면 화면에 지문이 하나 보입니다.

- 그 지문이 종이의 **③ 배포 열쇠 지문**과 **같으면** → 받아도 됩니다.
- **다르면 절대 받지 마세요.** 누군가 중간에서 가짜 서버 노릇을 하고 있을 수 있습니다.

★다른 사람의 폰에 이 안내를 하실 때는 **전화로 말해 주시거나 직접 만나서** 알려 주세요.
카톡·문자·웹페이지로 보낸 값은 근거가 되지 않습니다 — 열쇠를 바꿔치기할 수 있는 상대라면
그 메시지도 바꿀 수 있기 때문입니다.

받지 않아도 **걷기·정산·지불·수령은 그대로 됩니다.** 가진 코인도 그대로입니다.
받지 않으면 새 코스·새 목록만 안 들어올 뿐입니다.

## 이제 무엇이 달라지나

### ✅ 고쳐진 것

Render가 몇 번을 자고 깨든, 몇 번을 다시 배포하든 **열쇠가 그대로**입니다.
설치된 폰의 코스·신뢰 목록·소명 목록 동기화가 이제 끊기지 않습니다.

### ❌ 아직 안 고쳐진 것 — 이건 씨앗이 하는 일이 아닙니다

서버가 자고 깨어날 때마다 여전히 사라지는 것들이 있습니다.

- **회원 명부** — 다시 가입해야 하고, 그때 **새 회원 번호**가 나옵니다
- **지갑 백업** — 폰을 잃으면 코인을 되찾을 수 없습니다
- **마켓 거래 기록** — 입금된 돈을 내보낼 경로가 사라집니다
- **엔젤 보너스 받은 기록** — 같은 사람이 20 SHV를 또 받을 수 있습니다
- **사업자가 맡긴 예치 잔고** — 0이 됩니다

**그래서 지금 열 수 있는 파일럿은 "설치하고 걸으면 끝"까지입니다.**
걷기 → 정산 → 코인 만들기 → 얼굴 보고 QR로 주고받기 — 여기까지는 서버를 한 번도
부르지 않으므로 **완전히 안전합니다.** 가입·엔젤 등록·마켓을 여는 것은 그 다음 결정입니다.

이걸 고치려면 저장 공간을 돈 주고 사야 합니다(월 7달러 안팎으로 보입니다).
숫자는 제가 결제 화면에서 직접 본 것이 아니므로, 정하시기 전에 render.com의 가격
페이지를 한 번 보셔야 합니다. 판단 근거는 `docs/서버_키_지속성.md` 7장에 정리했습니다.

## 하지 마셔야 할 것

| 하지 말 것 | 왜 |
|---|---|
| 이미 넣은 씨앗을 **바꾸기** | 발행자를 통째로 갈아치우는 것과 같습니다. 이미 만든 코인의 근거가 흔들립니다 |
| 씨앗을 채팅·메일·사진에 남기기 | 그 순간 누구나 쉬빌 코인을 만들 수 있게 됩니다 |
| 씨앗 종이를 한 장만 두기 | 잃어버리면 되찾을 방법이 없습니다 |
| `SHVIL_KEY_GENERATION` 을 지금 건드리기 | 열쇠를 갈아치우는 스위치입니다. 지금은 필요 없습니다 |

### 씨앗이 새어 나간 것 같으면

**세대 올리기(`SHVIL_KEY_GENERATION`)로는 해결되지 않습니다.**
씨앗을 가진 사람은 다음 세대도 똑같이 만들어 낼 수 있기 때문입니다.
(예전 문서에 그렇게 하라고 적혀 있었는데, 그건 틀렸습니다. 고쳤습니다.)

그때는 **새 씨앗 = 새 발행자**가 되며, 문서·앱·이미 나간 코인 처리까지 딸린 큰 결정입니다.
혼자 결정하지 마시고 그 상황이 오면 다시 상의해 주세요.
자세한 설명은 `docs/서버_키_지속성.md` 6장에 있습니다.

## 저(개발)는 무엇을 안 했는가

- **git commit을 하지 않았습니다** (지시대로). 코드는 작업 폴더에만 있습니다.
- 라이브 서버를 건드리지 않았습니다. 위 절차는 **다니엘 쌤이 직접** 하셔야 합니다.
- 폰에서 「서버 열쇠 확인」 화면을 실제로 열어 보지 못했습니다 — 안쪽 로직은 테스트로
  확인했지만 **화면 자체는 실기기에서 한 번 봐야 합니다.**
