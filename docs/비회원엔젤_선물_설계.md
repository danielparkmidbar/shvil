# 비회원 트레일 엔젤에게 보물 숨기기 — 설계 (M13)

> 2026-07-20 다니엘 쌤 착안: **"보물 찾기의 역관계"** — 엔젤이 보물을 찾는 게 아니라,
> 쉬빌리스트가 **미래의 엔젤 앞으로 보물을 숨긴다.** 그 번호로 가입하는 엔젤은
> 계정이 없던 시절의 자기 봉사를 자동으로 코인으로 받는다.
>
> 4개 관점(헌법·프라이버시·총량보존·채택성) 설계 → 종합 → 3개 렌즈 적대검증 →
> 계획. 적대검증에서 **치명·높음 25건**이 나왔고, 그 결과 **이 기능은 현재 플랫폼
> 위에 올릴 수 없다**는 결론이 나왔다. 이 문서는 그 판단과 선행 조건을 기록한다.

## 1. 다니엘 쌤 요구

1. **지도**: 기존 INT 엔젤 명단(414명·169지점)을 대략적 위치 원으로 지도에 표시.
2. **보물 숨기기**: 신세를 진 하이커가, 엔젤이 **계정이 없어도** 그 앞으로 코인을 숨긴다.
3. **자동 수령**: 그 번호로 가입하면 **자동으로** 쌓인 보물을 받는다 (별도 청구 절차 없음).
4. 기능 위치: 숨기기·설명은 **쉬빌리스트**(하이커), 지도·수령 안내는 **쉬빌엔젤**.
5. **dev 모드에서는 비활성** (다니엘 쌤 확정 — 아래 §4 이유).

## 2. 핵심 난제와 해법 방향

**난제**: 코인 이전은 수령자의 공개키를 요구한다. 비회원 엔젤에겐 키가 없다 —
"보낼" 수 없다.

**해법**: M12 스팟 보물의 검증된 패턴을 그대로 쓴다 —
**헌납(리저브 소각) → 서버 회계 → 청구 시 동량 재발행.**
코인이 하이커에서 엔젤로 *이동*하는 사건은 계보에도 서버에도 존재하지 않는다.
하이커는 리저브로 소각하고, 서버는 번호 유도 버킷에 액수만 적립하며, 그 번호로
가입이 일어나면 적립분만큼 그랜트를 발행한다. 총량 보존은 M12와 같은 방식으로
성립한다 (발행 ≤ 적립).

**버킷 키**: 항목 순번이 아니라 **전화번호 유도 해시**로 잡는다
(`sha256('shvil-legacy-gift|' + E164)`). 위키가 편집돼도 이미 쌓인 적립이 다른
번호로 옮겨가지 않는다 — 항목 기반이었다면 필요했을 "운영자 검토 큐·동결" 같은
절차적 방어가 구조적으로 불필요해진다. `members.phone_hash`와는 도메인 분리한다.

## 3. 적대검증 결과 — 치명·높음 25건

세 렌즈(헌법위반·사기공격·코인분실)가 종합안을 공격해 나온 결과. 전문은 워크플로
산출물에 있고, 여기에는 **기능 자체를 막는 것**만 남긴다.

### 3-1. 플랫폼 결함 (이 기능이 만든 것이 아니라 **이미 배포 중인 것**)

| # | 결함 | 상태 |
|---|---|---|
| 치명 | `/spot/deposit`이 인간 한계를 검사하지 않아, 변조 앱이 부풀린 걷기 코인으로 무제한 슬롯 생성 | **✅ 2026-07-20 수리** (§5) |
| 치명 | `/spot/deposit`이 무결성 증서를 검증하지 않음 (`trustedRootKeys`·`requireIntegrityToken` 누락) | **✅ 2026-07-20 수리** (§5) |
| 치명 | 운영 배포가 `SHVIL_DEV_MODE=1` — OTP가 응답으로 노출된다. 공개 위키 번호로 아무나 남의 적립을 수령 가능 | ⛔ 미해결 |
| 치명 | Render 무료 티어는 재배포 시 SQLite가 초기화된다 — 적립 전액 소멸, 원리적 복구 불가 | ⛔ 미해결 |
| 높음 | `verifyGrant`가 모르는 kind에 fail-open (`900 > undefined` = false) — 새 kind 추가 시 구버전 지갑에서 상한이 사라진다 | ⛔ 미해결 |
| 높음 | 이 코드베이스에 트랜잭션·롤백 메커니즘이 없다 — 다단계 회계 중단 시 불일치 | ⛔ 미해결 |
| 높음 | 분할 재포크(같은 부모를 여러 번 SPLIT)로 같은 가치를 두 번 소각 가능, `checkFork`가 원리적으로 못 잡음 | ⛔ 미해결 |

### 3-2. 이 기능 고유의 위험

- **SMS 인프라 부재**: `app.ts`의 실 SMS 발송은 `TODO(운영)`이다. "기존 OTP 재사용"은
  사실이 아니며 신규 구축·비용이 필요하다. 이것이 자동 수령의 **유일한** 자격 증명이다.
- **청구 불가 번호**: 명단 중 번호 없음 14건, 비휴대(유선·기관) 번호 약 20건 —
  SMS OTP가 원천 불가하다. 이런 항목에 보물을 숨기게 두면 **영구 소각을 유도**하는
  것이라 제7조(선행의 순환)에 어긋난다. 선물 대상에서 사전 차단해야 한다.
- **공유 번호 11건**: 서로 다른 지점 항목이 한 번호를 쓴다. "자동 병합"은 이득이
  아니라 **첫 가입자가 남의 몫까지 가져가는 탈취**가 된다.
- **위키 번호 교체**: 공격자가 위키를 편집해 자기 번호를 넣으면 신규 선물을 낚을 수
  있다(기존 적립은 번호 결속이라 안전).
- **익명 괴롭힘 채널**: 감사 한마디를 무인증으로 허용하면 실명 공개된 439명을 향한
  무료·무추적 메시지 통로가 된다.

## 4. 판단 — 세 갈래로 쪼갠다 (제3조 정직화)

요구 1(지도)은 위 위험을 **하나도 공유하지 않는다.** 함께 묶어 미루는 것은 정직하지
않으므로 분리한다.

| 단계 | 내용 | 상태 |
|---|---|---|
| **M13-0** | 플랫폼 결함 수리 (§3-1) — 이 기능과 무관하게 **그 자체로 필요** | 2건 수리 완료, 나머지 대기 |
| **M13-A** | 지도 표시 (요구 1) — 독립 출시 가능 | 착수 가능 |
| **M13-B** | 보물 숨기기·자동 수령 (요구 2·3) — M13-0 완료 **후에만** | 차단됨 |

**dev 모드 비활성 (다니엘 쌤 확정)**: OTP가 노출되는 동안 이 기능을 열면 공개 위키
번호로 누구나 남의 적립을 수령할 수 있다. 실 SMS 연동 전까지 M13-B는 코드가 있어도
`devMode`에서 라우트를 등록하지 않는다.

### M13-B의 진짜 병목은 코드가 아니다

- **SMS 게이트웨이 조달** (사업자 선정·비용): 439명 × 발송 + 재발송 + 통지.
- **호스팅 결정**: 무료 티어의 ephemeral 디스크 위에 가치 발행 경로를 열면
  "대부분의 선물이 소멸한다"가 **정상 시나리오**가 된다. 유료 영구 디스크 /
  외부 DB / 다른 호스팅 중 택일이 선행되어야 한다.

작업량 감각: M13-A ≈ M12의 0.4배(+ 169지점 사람 검수), M13-B ≈ M12의 1.6배,
M13-0 ≈ M12의 1.0배(회귀 위험이 가장 높은 구간 — 이미 배포된 코드를 건드린다).

## 5. 즉시 수리된 것 (2026-07-20)

적대검증이 지적한 **이미 배포 중인 M12의 무제한 발행구**를 증명 테스트와 함께 막았다.

**공격**: 변조 앱은 `PendingWalkLedger`(일 400 dSHV 상한)를 우회하고 `SettlementDraft`를
손으로 지어 `buildWalkSegmentProof`에 바로 넘길 수 있다. `amountDshv`는 평범한 객체
필드이고 `verifyWalkSegmentProof`는 서명과 "일자합 = 총액" 정합만 본다. 그렇게 만든
5,000 dSHV(일 상한의 12.5배) 코인을 예치하면 **100슬롯이 생겨 진짜 TREASURE 그랜트로
재배포**됐다. 실제로 재현해 확인했다 (`server/test/spotForgery.test.ts`).

**수리**:
- `verifySpotDeposit`에 `EXCEEDS_HUMAN_LIMITS` 판정 추가 — 기존 `checkHumanLimits`
  (shared/humanLimits.ts) 재사용. 코인 자체의 증명이 인간 한계를 넘으면 예치 거부.
- `/spot/deposit`의 `verifyOptions`에 `trustedRootKeys`·`requireIntegrityToken` 추가
  — C 신뢰 지표(안 A)와 **같은 신뢰 루트**. 운영에서는 인증된 앱이 만든 코인만 가치가 된다.
- **거부하면서 동시에 소명 등재**한다(V-3 유지) — 예치는 막되(총량 보존) 세탁 시도가
  조용히 사라지지 않게(소명 책임).

여러 코인에 나눠 담아 개별 한도를 피하는 회피는 서버의 교차 합산 탐지
(`checkOverproduction`)가 소명 등재로 잡는 2층 방어다.

## 6. 다니엘 쌤 결정 대기

1. **출시 분리 승인**: 지도(M13-A)를 먼저 내고 선물(M13-B)은 플랫폼 수리 후로 미루는 것.
2. **SMS 게이트웨이**: 어느 사업자, 비용은 어떻게. (M13-B 차단 요인)
3. **호스팅**: 유료 영구 디스크 / 외부 DB / 다른 호스팅. (M13-B 차단 요인)
4. **웹 수령의 범위**: 코인 수령에는 기기 키가 필요해 브라우저 키 생성은 캐시 삭제 =
   영구 소실이다. "웹은 인증·잔액 확인·쪽지 읽기까지, 코인 수령은 앱"으로 갈 것인가,
   아니면 웹이 QR을 띄우고 앱이 스캔하는 방식인가.
