# 시각 앵커 사슬 — 원시 GNSS 없이 시각을 외부 사실에 묶는 설계 (조사 5)

> 2026-07-26. 조사·설계만. **코드 수정 0건, git 작업 0건.**
> 전제: 원시 항법 메시지도 OSNMA도 쓰지 않는다. 오늘 모든 안드로이드·아이폰에서
> 되는 것만으로 설계한다.

## 0. 정직화 — 조문 번호 정정

지시문이 인용한 "제3조 정직화 / 제10조 위치 비추적"은 `docs/쉬빌_헌법.md` 실물과 번호가
다르다. 실제로는 **제3조 = 속도보다 진리**, **제9조 (불간섭) = "걷는 자를 감시하지
않는다(위치 비저장)"**, **제10조 = 최종 목적지(식량 분배)**. 위치 비추적은 `CLAUDE.md`
핵심 사상 10번에도 있다. 저장소 전체가 위치 비저장을 **제9조**로 인용하므로
(`geoPrivacy.ts`, `authenticity.ts` 주석은 제10조로 잘못 적혀 있다) 이 문서는 제9조로 쓴다.

## 1. 문제의 정확한 형태

`packages/shared/src/proof.ts:22-24` — `startedAt`·`settledAt`·`dailyBreakdown[].date`가
전부 `proofPayload()` 서명 대상 안에 있다. 서명 키는 **같은 폰의 기기 키**다.
즉 "폰이 자기가 지어낸 시각에 자기 키로 서명"한다. 외부 근거가 0이다.

동시 진행 중인 다른 워크플로가 `authenticity.ts`에 절대량 상한 3종을 넣었다
(`WINDOW_TOO_LONG` 90일 / `BREAKDOWN_TOO_MANY` / `PROOF_CAP` 3,600 SHV).
이것으로 **한 장짜리** 43,800 SHV는 죽는다. 그러나 **남는 공격**이 있다:

> 오늘 가입한 기기가, 겹치지 않는 90일 창을 과거로 줄줄이 늘어놓는다.
> 10년 = 40개 창 × 3,600 SHV = **144,000 SHV**.
> `WINDOW_OVERLAP`은 창이 안 겹치므로 안 걸린다.
> `TIME_BUDGET`은 span이 진짜로 10년이라 안 걸린다.

상한은 **코인 자체 정합**이라 상한 안쪽은 통과시킬 수밖에 없다(60일 종주자를 살리려면
넉넉해야 하므로 필연). 이 공격을 죽이려면 **코인 바깥의 사실**이 필요하다.

### 무엇이 필요한가 — 방향이 결정적이다

- 위성·방송신호가 줄 수 있는 것: **하한**("이 시각보다 이르지 않다"). 방송된 것은 전부
  아카이브·재생 가능하므로 원리상 상한을 줄 수 없다.
- 백데이팅이 필요로 하는 것: **"주장된 startedAt이 실제보다 과거가 아니다"** = 과거
  방향의 벽.
- **과거 방향의 벽은 오직 증인(witness)만 세운다.** 그 시각에 외부에 커밋을 남겼다는
  사실 말고는 방법이 없다.

그래서 이 설계는 위성을 쓰지 않는다. 위성은 3층(장식)으로만 들어간다.

## 2. 설계 — 3층 구조

### 층 1. 기점 (Origin Pin) — **하중을 전부 받는 층. 아이폰·안드로이드 동일.**

`MembershipCertificate`에 필드 하나를 더한다.

```
deviceFirstSeenAt: number   // 이 기기 공개키가 서버에 처음 등록된 시각 (서버 서명 안)
```

- 서버는 이미 이 값을 갖고 있다 — `server/src/db.ts:14-22` `members` 테이블의
  `created_at` + `device_public_key`. **새 저장소 0.**
- 증서는 30일마다 갱신되지만(`server/src/app.ts:76` `MEMBERSHIP_CERT_TTL_MS`),
  `deviceFirstSeenAt`은 **갱신을 넘어 단조 불변**이다. 그래서
  `cert.issuedAt <= proof.startedAt` 같은 순진한 검사(정직한 옛 걷기를 죽인다)를
  쓰지 않아도 된다.
- 증서는 이미 `proofPayload()` 서명 대상 안에 있다(`proof.ts:23-24`). 즉 **증서
  바꿔치기가 이미 막혀 있다.** 새 서명 경로가 필요 없다.

**검사 (결정적 · FATAL):**

```
proof.startedAt >= cert.deviceFirstSeenAt − (시간대 관용 ±1일)
```

오늘 등록한 기기 키는 3년 전에 걸을 수 없었다. 10년 소급 144,000 SHV가 여기서 죽는다.
새 회원 번호를 남발해도 각 기기 키의 기점이 전부 "오늘"이므로 소급 총량이 0이 된다.

### 층 2. 앵커 사슬 (Anchor Chain) — **아이폰·안드로이드 동일. 상자를 닫는다.**

기점은 "가입 이후"라는 넓은 상자만 준다. 좁히려면 앵커가 필요하다.

**앵커 토큰** = 서버 루트 키(증서와 같은 키)가 서명한
`{ v, devicePublicKey, chainHead, issuedAt: T, nonce: R, issuerKeyId, issuerPublicKey, signature }`

지갑은 `PendingWalkLedger`에 해시 사슬 머리를 하나 얹는다(좌표 없음, 기존 파생 지표만):

```
H_0 = hash(deviceFirstSeenAt)
H_n = hash(H_{n-1} ‖ 창요약_n ‖ 소비한_앵커논스들)
```

두 방향이 각각 다른 일을 한다:

| | 재료 | 얻는 것 |
|---|---|---|
| **하한** | 앵커의 `nonce: R` 를 이후 창의 사슬에 접어 넣는다. R은 T 이전에는 누구도 예측할 수 없다. | 그 창은 **T 이후**에 만들어졌다 |
| **상한** | 서버가 `chainHead = H_n` 에 서명해 준다. | H_n 에 들어간 모든 창은 **T′ 이전**에 존재했다 |

두 앵커 사이의 창은 **`(T, T′]` 상자 안에 갇힌다.** 백데이팅도 미래날짜도 죽는다.

**오프라인 하한 — 종주자를 위한 장치.** 앵커 토큰의 `nonce`는 무기명(bearer)이다.
지갑 A가 만난 지갑 B에게 자기가 가진 최신 서버 앵커를 그대로 넘겨줄 수 있다. B는
서버에 닿지 않고도 "지금은 T 이후다"라는 **서버 서명 하한**을 얻는다. 지갑이 이미
메신저이고 코인 전송이 QR 왕복이므로, 만남이 곧 시각 배급이다(제7조 순환의 원리와
같은 모양이다).

**오프라인 상한 — 동료 증인.** 코인 전송 QR 왕복에서 상대 지갑이
`(내 chainHead, 상대의 시각 주장, 상대가 가진 최신 서버 앵커)`에 반서명해 준다.
암호적 불가능이 아니라 **"두 회원 번호가 함께 거짓말해야 뚫린다"**는 벽이다.
소명 책임·커뮤니티 모니터링(핵심 사상 3)이 받는 층이며, 등급에서 그렇게 표시한다.

**증명에 새로 들어가는 필드** (전부 `proofPayload()` 안 = 서명 대상):

```
timeAnchors?: {
  opening: AnchorToken | null;   // 하한 (없으면 기점이 하한)
  closing: AnchorToken | null;   // 상한 (없으면 수신자 시계가 상한)
  peerClosing?: PeerWitness | null;
  chainHead: string;             // 이 증명이 덮는 사슬 머리
}
```

**좌표는 한 글자도 없다.** 앵커는 시각과 해시뿐이다.

### 층 3. GNSS 시각 대조 (안드로이드 전용) — **장식. 아무 하중도 받지 않는다.**

안드로이드 `Location.getTime()` 공식 문구(직접 확인):

> "Locations derived from the `LocationManager#GPS_PROVIDER` are guaranteed to have
> their time originate from the clock in use by the satellite constellation that
> provided the fix. Locations derived from other providers may use any clock to set
> their time, though it is most common to use the device's Unix epoch time system
> clock (which may be incorrect)."

**★ 그런데 지금 코드로는 안 된다.** `expo-location`은 안드로이드에서
`FusedLocationProviderClient`를 쓴다
(`LocationModule.kt:138` `LocationServices.getFusedLocationProviderClient`), 그리고
`LocationResults.kt`의 `LocationResponse(location)`은 `timestamp = location.time`을
그대로 넘긴다. Fused는 **시스템 시계**를 쓴다 — 제3자 실측(기기 시각을 이틀 뒤로
돌린 실험)에서 `GPS_PROVIDER`만 진짜 시각을 냈고 Fused와 Network는 조작된 시각을 냈다.

따라서 이 층을 쓰려면 `LocationManager.GPS_PROVIDER`를 직접 여는 **작은 네이티브
모듈**이 필요하다. 새 권한은 없다(ACCESS_FINE_LOCATION 이미 보유,
`walkService.ts:39`). 개발 빌드가 필요하지만 `walkService.ts:7-9`가 이미 개발 빌드가
필요하다고 적어 두었으므로 신규 부담이 아니다.

**기록하는 것은 스칼라 하나뿐:**

```
gnssClockSkewMs: number   // (위성 시각 − 시스템 시각) 의 창별 중앙값
```

위성 번호도, 개수도, 고도각도, 좌표도 **기록하지 않는다.** 조사 4가 수치로 보였듯
가시 위성 집합은 다중 에폭에서 관측 위치를 10 km 급으로 역산하고, 코스는 1차원
곡선이라 앵커 하나가 곧 전부다 — 제9조 정면 위반이다. **위성 배치는 어떤 형태로도
코인에 넣지 않는다.**

## 3. 등급 — 그리고 등급이 실제로 무엇을 바꾸는가

증명 한 건의 **시각 근거 등급**:

| 등급 | 조건 | 시각에 대해 말할 수 있는 것 |
|---|---|---|
| **T0 기점만** | 증서만 있음 | `deviceFirstSeenAt ≤ startedAt ≤ 수신자의 now` |
| **T1 하한** | 여는 앵커 있음 | `T ≤ startedAt` — 서버 서명 하한 |
| **T2 닫힌 상자** | 여는 + 닫는 서버 앵커 | `T < 모든 창 ≤ T′` — 소급·미래 둘 다 죽음 |
| **T2p 동료 증인** | 닫는 쪽이 동료 반서명 | 같은 상자. 단 **두 회원이 공모하면 뚫린다** |
| **T2+ 위성 대조** | T2 + 안드로이드 skew 기록 | 암호적으로 **아무것도 더하지 않는다** |

### 등급이 바꾸는 것 — 정확히

**1. 발행액을 바꾸지 않는다. 하나도.**
T0 코인과 T2 코인은 같은 거리에서 같은 SHV를 만든다. 요율·상한·계수 전부 동일하다.
아이폰 사용자가 손해 보는 지점이 **없다**(제7조).

**2. 민팅을 막지 않는다.**
앵커가 하나도 없어도 코인은 만들어지고, 서명은 유효하고, 계보는 정상이다.
"앵커 없으면 코인 안 만들어진다"는 설계는 **명시적으로 금지한다** — 그것이 0층 파괴다.

**3. `coreVerdict`는 등급이 아니라 모순으로만 움직인다.**
`authenticity.ts`의 구조를 그대로 쓴다:
- 앵커·기점이 **있는데 어긋나면** → `FATAL` (`ANCHOR_INVALID`, `BEFORE_ORIGIN`).
  10년 소급 공격이 정확히 여기서 죽는다.
- 앵커가 **없으면** → 발견 0건. `notes`에 한 줄만 남긴다:
  *"이 코인의 시각에는 외부 근거가 없습니다(T0). 검사하지 못한 범위입니다."*
  이것이 제3조 정직화다 — 없는 것을 벌하지 않고, 없다고 말한다.

따라서 **아이폰이든 오프라인이든 코어 판정이 나빠지지 않는다.** 세상 누구의 기기에서든
같은 `coreVerdict`가 나온다는 성질(화폐성)이 유지된다.

**4. 리포트가 사실을 말한다 — 판단이 아니라 계량.**

```
timeEvidence: { anchoredDshv, halfDshv, bareDshv }
```

"이 지갑 12,400 dSHV 중 9,800은 닫힌 상자 안, 2,600은 기점만." 숫자다. 점수가 아니다.

**5. 각자의 선은 규칙 팩으로 긋는다 (제9조 무승인).**
`rulePacks/strictBuyer.ts` 패턴 그대로. 마켓 대량 매입자가
*"500 SHV 넘는 코인은 T2만 받겠다"* 는 팩을 얹을 수 있다. 그것은 **그 사람의 기준**이고
팩 발견으로 표시되며 코어를 완화할 수 없다. 화폐가 두 등급으로 쪼개지지 않는다.

**6. 지갑 UI는 한 줄.**
"시각 근거: 닫힌 상자 / 하한만 / 기점만". 색깔 등급도, 별점도, 경고 아이콘도 없다.

### 아이폰이 배제되지 않는 이유 — 구조적으로

층 1·2는 **센서를 하나도 쓰지 않는다.** 서버 서명과 해시 사슬뿐이다.
따라서 **아이폰은 T2까지 안드로이드와 완전히 동일하게 도달한다.**
아이폰이 못 받는 것은 T2+ 하나이고, T2+는 위에서 못 박았듯 **암호적으로 아무것도
더하지 않는 장식**이다. 배제되는 폰이 없다.

(정직화: 그 대신 아이폰은 `server/src/integrity.ts` 주석대로 App Attest 미연동이라
증서 `integrity`가 UNVERIFIED로 남는다. **이건 이 설계가 만든 격차가 아니라 이미
있던 격차**이며, 여기서 해결하지 않는다.)

## 4. 버린 재료 — 왜 버렸는가

**보이는 위성 개수·번호 (GnssStatus)** — 버린다.
- 아이폰은 위성 **개수조차** 주지 않는다(Apple 엔지니어 답변). 구조적으로 안드로이드 전용.
- 제9조 위반: 조사 4 실측에서 다중 에폭 가시집합이 관측 위치를 5시간에 10.5 km,
  마스크 15°에서도 7.1 km로 좁혔다. 코스는 1차원 곡선이고 거리는 이미 코인에 있으므로
  앵커 하나면 궤적 전부가 따라온다.
- 위조 방어력 ≈ 0: 과거 임의 시점의 궤도력이 CelesTrak·BKG에 **로그인 없이** 공개돼
  있고, 조사 3 실측 기준 하늘 지문 1회 계산이 **0.9 ms**다. 검증기가 하는 계산과
  공격자가 하는 계산이 완전히 같다.

**위치 정확도(accuracy) 시계열** — 버린다.
- **시각에 대해 아무 말도 하지 않는다.** 이 작업의 목적에 기여하지 않는다.
- 통계 신호로만 쓸 수 있는데(`SIGNAL`), 검사가 공개되는 순간 흉내가 쉽다.
- 게다가 accuracy 시계열은 그 자체가 **지문**이라 서로 다른 걷기를 연결할 수 있다.
  얻는 것보다 잃는 것이 크다.

**세션 내 단조 시계(`performance.now()`) 대 벽시계 비교** — 부가 신호로만.
- 크로스플랫폼·무권한·무배터리이고 시계 점프를 **탐지**할 수 있다.
- 그러나 탐지값 자체가 폰의 보고다. 변조 앱은 그냥 "점프 없었음"이라 쓴다.
- **증거가 아니라 정직한 앱의 자기 신고**다. 등급에 넣지 않는다.
- (RN/Hermes에서의 정확한 단조성 보장은 **미확인** — 실기기 확인 안 했다.)

## 5. 제9조·0층 대조

**제9조 (위치 비저장)** — 무해하다.
- 앵커에 들어가는 것: 시각, 논스, 기기 공개키, 불투명 해시. **좌표 0.**
- 서버가 새로 알게 되는 것: "이 기기 키가 T에 온라인이었다" + 뒤집을 수 없는 해시.
  증서 갱신·디렉토리 동기화가 이미 같은 등급의 메타데이터를 남긴다. **새 노출 없음.**
- 수신자가 새로 알게 되는 것: "이 회원이 T와 T′에 온라인이었다". 코인에는 이미
  `memberId`와 `startedAt`이 평문으로 있다. **연결 가능성이 늘지 않는다.**

**0층 ("설치하고 걸으면 끝")** — 깨지 않는다.
- 걷기·정산·거래 전부 오프라인 그대로. 앵커 0개로도 코인이 나오고 금액이 같다.
- 새로 요구되는 온라인 순간이 **없다**. 이미 있는 가입·30일 갱신 경로에 숫자 하나와
  토큰 하나를 얹을 뿐이고, 앵커는 지갑이 어떤 이유로든 서버에 닿을 때 곁다리로 받는다.
- 유일한 실질 변화: **가입 시점이 그 기기의 발행 가능 과거 경계가 된다.** 설치 전
  걷기는 애초에 기록이 없으므로 정직한 사용자 손실 0.

**깨지는 경우 (금지 사항으로 명시):**
- 앵커를 민팅 필수 조건으로 만들면 → 즉시 0층 파괴.
- 등급으로 요율을 깎으면 → 제7조·0층 파괴.
- 위성 재료를 필수로 만들면 → 아이폰 전멸.

## 6. 증명하지 못하는 것 (제3조)

1. **걸었다는 것을 증명하지 않는다.** 앵커는 "이 데이터가 두 시각 사이에 만들어졌다"만
   말한다. 변조 앱은 상자 안에서 걷지 않고 거리·걸음을 지어낼 수 있다. 달라지는 것은
   하나뿐이다 — **이제 실시간으로만 지어낼 수 있고, 하루 40 SHV 상한에 걸린다.**
   공격 수익이 "소급 일수에 비례"에서 "흘러간 실제 시간에 비례"로 바뀐다. 이 설계의
   전부가 이것이다.
2. **위치를 증명하지 않는다.** 증명하려 하지도 않는다(제9조).
3. **GNSS skew는 암호적 증거가 아니다.** 서명이 없다. 변조 앱은 숫자를 지어낸다.
   무결성 토큰 VERIFIED와 함께일 때만 의미가 생기고, 아이폰은 지금 UNVERIFIED다.
4. **앵커 서버가 거짓 시각에 서명하면 전부 무너진다.** 신뢰 루트가 늘지는 않는다
   (증서와 같은 키). 그러나 서버가 사라지면 새 앵커를 못 받는다 — 기존 코인 검증은
   계속되지만 새 T2는 안 나온다. **무승인 원칙과의 긴장이 여기 있다.** 동료 증인이
   그 긴장을 덜지만 공모에 뚫린다.
5. **시계 되돌리기를 폰 안에서 탐지할 수는 있어도 증명할 수 없다.**
6. **T0 구간에 대해서는 오늘과 정확히 같은 정도로 아무것도 증명하지 못한다.**
   층 1의 기점 하나를 빼면.

## 7. 확인하지 못한 것 (미확인)

1. `LocationManager.GPS_PROVIDER`의 `getTime()`이 **내가 쥔 실기기에서** 위성 시각을
   주는지 — 1차 문서(javadoc)와 제3자 실험 보고까지만 확인했다. 안드로이드 기기로
   실행하지 않았다.
2. GPS Week Number 롤오버 버그로 일부 기기의 `GPS_PROVIDER` 시각이 어긋난다는 보고가
   있다. 실제 발생률 미확인 — 층 3을 하중에서 뺀 이유 중 하나다.
3. iOS `CLLocation.timestamp`가 시스템 시계를 따르는지 1차 문서로 확정하지 못했다.
   (설계가 이 값을 쓰지 않으므로 결론은 바뀌지 않는다.)
4. RN/Hermes `performance.now()`의 단조성 보장 범위.
5. 144,000 SHV 잔존 공격을 **내가 실행해 재현하지 않았다.** `authenticity.ts`의
   `WINDOW_OVERLAP`·`TIME_BUDGET` 코드를 읽고 논증한 것이다.
6. 앵커 사슬을 `PendingWalkLedger`의 영속화 스냅숏(`PendingLedgerState`)에 얹을 때의
   마이그레이션·하위 호환 순서. 설계만 했고 코드는 손대지 않았다.
