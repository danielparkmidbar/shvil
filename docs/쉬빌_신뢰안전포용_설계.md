# 쉬빌 코인 신뢰·안전·포용 시스템 설계서

**작성**: 신뢰·안전·포용부 (Trust, Safety & Inclusion)
**버전**: 초안 v0.1 (창립자 검토용)
**작성일**: 2026-07-12

---

## 기조 선언

> **"누구도 배제하지 않되, 모두가 안전한 자리에서 만나게 한다."**

이 문서의 모든 설계는 위 한 문장에서 출발합니다. 쉬빌 생태계의 신뢰·안전 시스템은 "누구를 걸러낼 것인가"를 묻지 않습니다. **"이 사람에게 맞는 자리는 어디인가"**를 묻습니다.

- 안전 장치는 문을 잠그는 자물쇠가 아니라, 각 사람을 올바른 문으로 안내하는 **이정표**입니다.
- 확인(verification)의 목적은 의심이 아니라, **엔젤이 안심하고 문을 열 수 있게 하는 것**입니다. 본인 확인이 보장될수록 더 많은 엔젤이 참여한다는 것이 창립자의 판단이며, 이 설계는 그 판단을 시스템으로 구현합니다.
- 가장 도움이 필요한 사람(정신건강 위기, 범죄 전력, 사회적 고립)이 시스템 밖으로 밀려나는 순간, 이 프로젝트는 실패합니다. 그들을 **일반 가정이 아닌 전문적인 자리**에서 받아들이는 경로를 시스템 안에 내장합니다.

### 설계의 출발점: 창립자의 직접 경험

| 경험 | 설계 반영 |
|---|---|
| 엔젤과 리스트는 현재 WhatsApp 전화로 소통한다. 모두 전화가 있다. | **전화번호 인증을 레벨 0의 기반**으로 삼는다. 새 습관을 강요하지 않고 기존 행동 위에 시스템을 얹는다. |
| 팀보다 솔로 여행자를 받는 부담이 크다. 어떤 사람인지, 왜 홀로 걷는지 모르기 때문이다. | **솔로 리스트 전용 신뢰 신호 체계**(배지·후기·첫 이용자 프로토콜)를 별도 설계한다. |
| 정신질환으로 방황하던 쉬빌리스트를 실제로 만났다. | **비낙인적 위기 식별과 전문 엔젤 연결 경로**를 설계한다. 배제가 아니라 더 전문적인 수용이 목적이다. |
| 범죄 기록이 있는 사람도 시스템 안에 수용하려 한다. | **등급별 수용처(공공형 쉬빌 홈 → 전문 엔젤 → 일반 가정)** 구조를 설계한다. |

## 1. 본인 확인(KYC) 단계 설계

### 1.1 설계 원칙

1. **비례성**: 요구하는 신원 정보의 깊이는 그 행위의 위험 크기에 비례한다. 앱을 열어보는 데 신분증을 요구하지 않고, 현금화하는 데 전화번호만으로 허용하지 않는다.
2. **점진성**: 걷기 시작하는 문턱은 최대한 낮게, 돈이 움직이는 문턱은 규제 수준으로. 리스트는 순례 중에 자연스럽게 레벨을 올린다.
3. **현실 기반**: 순례길 위의 모든 사람이 이미 가진 것 — 전화 — 에서 출발한다.

### 1.2 레벨 구조

#### 레벨 0 — 전화번호 인증 (문턱 없는 입장)

| 항목 | 내용 |
|---|---|
| 확인 수단 | SMS/WhatsApp OTP를 통한 전화번호 소유 확인 |
| 허용 행위 | 앱 열람, 경로·엔젤 지도 조회(연락처 비공개 상태), 걷기 기록(만보계·GPS 트랙), 커뮤니티 게시글 열람 |
| 코인 관련 | 걷기 기록은 축적되나 **코인은 아직 발행되지 않음** (레벨 1 도달 시 소급 발행 가능 — "걸은 것은 사라지지 않는다") |
| 근거 | 현재 엔젤-리스트 소통이 이미 전화 기반이므로, 전화번호는 생태계의 자연스러운 최소 신원 단위 |

- 걸은 기록의 소급 발행 인정 기간(예: 90일)은 미해결 쟁점 8.3 참조.

#### 레벨 1 — 신분증 확인 (사람과 사람이 만나는 문)

| 항목 | 내용 |
|---|---|
| 확인 수단 | 정부 발행 신분증(여권·주민등록증·운전면허증) 촬영 + 얼굴 대조(liveness check). 국제 순례자를 고려해 **여권을 1순위 표준**으로 |
| 허용 행위 | **코인 발행(걷기→코인 전환)**, 엔젤에게 대면 지불, 엔젤 연락처 열람 및 예약 요청, 후기 작성 |
| 엔젤 요건 | **엔젤 등록은 최소 레벨 1 필수** (자기 집을 여는 사람의 신원은 확인되어야 하고, 리스트도 엔젤을 신뢰할 근거가 필요함 — 신뢰는 양방향) |
| 저장 원칙 | 신분증 원본 이미지는 검증 후 파기 또는 암호화 격리 저장, 앱과 매칭 시스템에는 "레벨 1 검증됨" 플래그와 검증된 실명·생년만 보관 (6장 참조) |

#### 레벨 2 — 강화 확인 (돈이 시스템 밖으로 나가는 문)

| 항목 | 내용 |
|---|---|
| 확인 수단 | 레벨 1 + 주소 확인(공과금 고지서 등) + 은행 계좌 실명 대조 + 제재 목록(sanctions)·PEP 스크리닝 |
| 허용 행위 | 코인 **현금화(법정화폐 환전)**, 마켓플레이스 고액 거래, 엔젤의 수익 정산 출금 |
| 추가 통제 | 거래 한도(일/월), 이상 거래 모니터링, 규제 당국 보고 체계 연동 |

### 1.3 금융 규제(AML)와의 관계

- **레벨 0–1은 폐쇄 루프(closed-loop) 커뮤니티 포인트**에 가깝게 설계한다: 걷기로만 발행되고, 생태계 내부(엔젤 숙박·식사)에서만 소비되며, 외부 환전이 불가능한 동안에는 다수 법역에서 전자화폐/가상자산 규제의 완화 적용 또는 면제 여지가 있다.
- **레벨 2에서 법정화폐 접점이 열리는 순간** AML/CFT 의무(고객확인, 거래기록 보존, 의심거래 보고)가 본격 적용된다. 따라서 레벨 2의 KYC 요건은 "우리가 정한 것"이 아니라 "규제가 요구하는 것"이며, 이를 사용자에게 그대로 설명한다: **"걷고 머무는 데는 최소만, 돈을 바꾸는 데는 법이 요구하는 만큼."**
- 운영 법인의 라이선스 전략(전자금융업 등록, VASP 신고, 또는 규제 샌드박스)은 서비스 개시 국가(스페인/한국/기타)에 따라 달라지므로 미해결 쟁점 8.1로 이관한다.
- **레벨 간 하향 원칙**: 상위 레벨 검증이 만료·철회되어도 하위 레벨 권한은 유지된다. 검증 실패가 곧 추방이 아니다.

## 2. 엔젤의 선택권 설계

### 2.1 원칙: 문을 여는 사람이 문의 폭을 정한다

엔젤은 자기 집을 내어주는 자원봉사자다. 시스템이 엔젤에게 "누구든 받아야 한다"고 강요하는 순간 엔젤은 떠난다. 반대로 엔젤이 안심할수록 문은 더 넓게 열린다. 따라서 **수용 조건의 결정권은 전적으로 엔젤에게** 있으며, 시스템은 그 조건을 표현·집행하는 도구만 제공한다.

### 2.2 수용 조건 설정 (Angel Preferences)

엔젤이 프로필에서 스스로 설정하는 필터:

| 조건 유형 | 예시 옵션 |
|---|---|
| 인원 구성 | 팀(2인 이상)만 / 솔로 가능 / 솔로는 여성만 / 가족 단위만 |
| 성별 | 제한 없음 / 여성만 / 남성만 (엔젤 본인의 안전 판단 존중) |
| 검증 레벨 | 레벨 1 이상만 / 레벨 2 이상만 |
| 이력 | 완주 배지 보유자만 / 후기 N개 이상 / 첫 이용자 수용 여부 |
| 수용 형태 | 방 / 마당(텐트) / 처마(비가림) / 식사만 / 샤워만 |
| 시기 | 수용 가능 요일·계절, 최대 연속 숙박일 |
| 전문 수용 | 전문 엔젤 자격 보유 시: 위기 연계 수용 가능 여부 (4장 참조) |

- 조건에 맞지 않는 리스트에게 해당 엔젤은 **검색 결과에서 처음부터 노출되지 않는다.** "요청 후 거절"은 양쪽 모두에게 상처가 되므로, 사전 필터링으로 거절 자체가 발생할 상황을 줄인다.
- 엔젤은 조건과 무관하게 **개별 요청을 사유 설명 없이 거절할 권리**를 가지며, 거절은 엔젤의 평판에 불이익을 주지 않는다.

### 2.3 리스트 프로필 공개 수준

리스트 프로필은 이중 구조로 한다.

| 정보 | 공개 범위 |
|---|---|
| 닉네임, 프로필 사진, 검증 레벨 배지, 걷기 통계(누적 km, 완주 이력), 후기 요약 점수 | 검색 단계에서 엔젤에게 공개 |
| **검증된 실명, 나이대, 국적, 이전 엔젤들의 후기 전문** | **예약 요청을 보낸 시점부터** 해당 엔젤에게만 공개 |
| 전화번호 | 엔젤이 요청을 수락한 시점부터 상호 공개 (기존 WhatsApp 소통 흐름과 연결) |
| 민감 정보(정신건강, 범죄 기록 등) | **어떤 경우에도 엔젤에게 비공개** (6장 참조) |

### 2.4 상호 사전 확인 흐름

```
[리스트] 조건에 맞는 엔젤 검색
   ↓
[리스트] 예약 요청 전송 (도착 예정일, 인원, 필요 항목)
   ↓  → 이 시점에 리스트의 실명·후기 전문이 엔젤에게 공개
[엔젤] 프로필 검토 → 수락 / 거절 / 대화 요청
   ↓  → 수락 시 상호 전화번호 공개, WhatsApp/앱 내 통화 가능
[양측] 사전 통화 (권장 절차 — 현재 관행의 공식화)
   ↓
[대면] 도착 시 앱 내 QR 상호 확인 (프로필 사진·이름 대조)
   ↓
[체류 후] 코인 지불 + 상호 후기 (후기는 양측 모두 작성 완료 또는 14일 경과 후 동시 공개 — 보복성 후기 방지)
```

## 3. 솔로 리스트 대응

### 3.1 문제 정의

창립자의 경험대로, 엔젤에게 가장 큰 부담은 솔로 여행자다. "어떤 사람인지, 왜 홀로 걷는지 모른다"는 두 가지 불확실성이 핵심이다. 해법은 솔로를 제한하는 것이 아니라 **솔로에 대한 정보의 밀도를 높이는 것**이다.

### 3.2 솔로 리스트의 신뢰 신호 체계

| 신호 | 내용 |
|---|---|
| **검증 배지** | 레벨 1/2 배지, 여권 검증 국가 표시 |
| **걷기 발자국** | GPS 기반 누적 걷기 기록 — "이 사람은 실제로 지난 12일간 280km를 걸어왔다"는 사실 자체가 강력한 신뢰 신호 |
| **엔젤 후기 체인** | 이전 엔젤들의 후기가 시간순으로 연결됨. "사흘 전 A 엔젤 집에 머물렀고 좋은 평가를 받았다"는 것은 신원 조회보다 강한 사회적 보증 |
| **자기소개 항목** | "왜 걷는가"를 쓰는 선택적 자기소개란. 엔젤의 두 번째 불확실성("왜 홀로 걷는가")에 리스트가 스스로 답할 기회를 준다. 작성은 자유이나 작성 시 매칭률이 높아진다는 점을 안내 |
| **보증인(Voucher)** | 완주 경력자·엔젤·순례 단체가 특정 리스트를 보증할 수 있는 기능. 보증인의 평판이 함께 걸림 |

### 3.3 첫 이용자 프로토콜 (First Walk Protocol)

후기가 0개인 솔로 리스트의 콜드 스타트 문제를 푸는 절차:

1. **첫 1–2박은 공공형 쉬빌 홈 또는 "첫 손님 환영" 엔젤에서**: 직원이 상주하거나, 신규자 수용 경험이 많고 자원한 베테랑 엔젤(추가 코인 보상 인센티브)에게 배정.
2. **첫 후기 획득**: 여기서 받은 첫 후기가 이후 일반 가정 매칭의 씨앗이 된다.
3. **점진 개방**: 후기 1개 이상 + 걷기 기록 누적 시 일반 엔젤 검색 결과에 정상 노출.
4. 팀(2인 이상) 리스트는 이 프로토콜을 건너뛸 수 있다 (엔젤 부담이 원래 낮으므로).

## 4. 취약계층 수용 프로토콜

### 4.1 원칙

정신건강의 어려움을 겪는 순례자는 걸러낼 대상이 아니라 **이 길이 가장 필요한 사람**이다. 창립자의 말대로, 그들은 "보다 전문적인 사람들이 전문적인 시설에서" 받아들이면 된다. 시스템의 역할은 진단이 아니라 **안내(routing)**다.

### 4.2 비낙인적 식별 — 진단하지 않고 신호를 본다

시스템은 누구에게도 "정신질환자" 딱지를 붙이지 않는다. 대신 **행동 신호**와 **자발적 요청** 두 경로만 사용한다.

**(a) 자기 요청 (가장 우선)**
- 앱 내 상시 버튼: **"지원이 필요한 여정"** — 리스트 본인이 "혼자 걷기가 힘들다, 돌봄이 있는 숙소가 좋겠다"고 표시할 수 있다. 사유 입력은 요구하지 않는다.
- 이 표시는 불이익이 아니라 혜택(전문 엔젤 우선 배정, 체크인 콜)으로 연결되도록 설계해 자발적 사용을 유도한다.

**(b) 행동 신호 (자동, 비공개)**
- 예: 심야의 비정상 이동 패턴, 예약 후 반복 무단 불참, 엔젤들의 우려 신고(2건 이상), 위기 언어가 포함된 지원 요청.
- 신호는 점수화되어 **신뢰·안전팀 내부에만** 표시된다. 엔젤·다른 리스트에게는 절대 노출되지 않는다.
- 신호 감지 시 시스템의 첫 반응은 제재가 아니라 **연락**이다: 훈련받은 담당자가 안부 확인 전화를 한다 (전화 기반 생태계의 장점 활용).

**(c) 엔젤 대상 안내 교육**
- 엔젤 온보딩에 15분 분량의 "우려될 때 어떻게 하나요" 모듈 포함: 판단하지 말 것, 24시간 지원 라인 번호, 우려 신고 방법. 엔젤에게 진단자 역할을 기대하지 않는다.

### 4.3 3단계 연결 경로

```
1단계  일반 가정 엔젤
        │  본인 요청 또는 우려 신호 감지 시
        ▼
2단계  전문 엔젤 (Trained Angel)
        - 정신건강 응급처치(MHFA 등) 훈련을 이수한 자원봉사 엔젤
        - 사회복지사·간호사·상담사 출신 자원봉사자 우선
        - 추가 코인 보상 + "전문 엔젤" 명예 배지
        │  전문적 개입이 필요하다고 판단될 때
        ▼
3단계  제휴 기관 (Partner Shelter)
        - 지역 복지기관, 순례길 인근 쉼터, 교회·수도원 숙소, 의료기관
        - 시스템은 "연결"까지만 하고 이후는 기관의 전문 프로토콜을 따름
```

- 각 단계 이동은 **강제가 아니라 제안**이다. 본인이 거부하면 존중하되, 즉각적 위험(4.5)의 경우만 예외로 한다.
- 상위 단계에 머무는 것이 코인 사용에 불이익을 주지 않는다: 전문 엔젤·제휴 기관 숙박도 동일하게 코인으로 지불 가능.

### 4.4 지역 복지·의료 기관 제휴 모델

| 제휴 유형 | 내용 | 기관의 유인 |
|---|---|---|
| 쉼터형 제휴 | 순례 구간별 1개 이상의 제휴 쉼터 확보, 위기 시 우선 수용 협약 | 코인 정산(레벨 2 법인 계정) 또는 기부금, 이용 통계 제공 |
| 의료 자문 | 지역 정신건강센터·병원과 24시간 자문 핫라인 협약 | 지역사회 공헌 실적, 위기 조기 개입 |
| 훈련 제휴 | 복지기관이 전문 엔젤 훈련 커리큘럼 제공·인증 | 자원봉사 인력 풀 확대 |
| 데이터 제휴 | 익명·통계 수준의 위기 발생 데이터 공유 (개인 식별 불가) | 지역 복지 계획 수립 자료 |

### 4.5 위기 상황 대응 절차 (Crisis Protocol)

즉각적 자·타해 위험이 인지된 경우:

1. **생명 우선**: 현지 응급번호(112/119, 유럽 112) 연락이 항상 1순위. 앱은 현 위치 기준 응급 연락처를 원터치 제공.
2. **24시간 지원 라인**: 신뢰·안전팀 상시 대응 라인. 엔젤·리스트 누구나 호출 가능.
3. **엔젤 보호**: 위기 상황이 발생한 엔젤 가정에는 사후 브리핑과 심리적 지원을 제공하고, 해당 엔젤이 원하면 일정 기간 매칭 중단. **엔젤에게 위기 대응 책임을 지우지 않는다.**
4. **사후 경로 재배정**: 위기를 겪은 리스트는 퇴출이 아니라 3단계 경로(전문 엔젤/제휴 기관)로 재배정된다. 회복 후 본인 의사에 따라 일반 경로 복귀 가능.
5. **기록 최소화**: 위기 기록은 사유 없이 "경로 조정됨"으로만 시스템에 남기고, 상세 기록은 격리 저장 후 보존 기한(제안: 2년) 경과 시 파기.

## 5. 범죄 기록자 수용 정책

### 5.1 철학: 길은 원래 속죄하는 자의 것이었다

순례길은 역사적으로 참회와 재출발의 길이었다. 범죄 기록이 있는 사람을 배제하는 것은 이 길의 본질에 반한다. 다만 **"수용한다"와 "아무 집에나 배정한다"는 다르다.** 해법은 수용처의 등급화다.

### 5.2 등급별 수용처

| 수용처 | 성격 | 수용 대상 |
|---|---|---|
| **공공형 쉬빌 홈** | 직원(또는 훈련된 관리 자원봉사자)이 상주하는 공동 숙소. 재단 직영 또는 제휴 기관 운영 | 모든 리스트에게 열려 있음. 중대 전력자·심사 대기자·첫 이용자의 기본 수용처 |
| **전문 엔젤** | 교정·재활·사회복지 경력의 훈련받은 자원봉사 엔젤. 본인이 명시적으로 자원한 경우만 | 심사를 통과한 경미·중간 전력자, 재활 프로그램 연계자 |
| **일반 가정 엔젤** | 일반 자원봉사 가정 | 무전력자 및 심사에서 일반 수용이 승인된 자 |

핵심: **어느 등급에서든 걷고, 코인을 벌고, 지불하고, 완주할 수 있다.** 등급은 "머무는 곳"만 다르게 할 뿐 "순례자로서의 자격"을 다르게 하지 않는다.

### 5.3 자기 신고와 심사 절차

1. **자기 신고 우선주의**: 가입 시 전과 조회를 강제하지 않는다(다수 법역에서 법적으로도 불가). 대신 "지원이 필요한 여정" 옵션처럼, **자기 신고 시 불이익이 아닌 명확한 경로**(공공형 쉬빌 홈 무조건 이용 가능)를 제공한다. 숨길 이유를 줄이는 것이 강제 조회보다 실효적이다.
2. **심사 위원회**: 자기 신고자 중 전문 엔젤/일반 가정 수용을 원하는 경우, 신뢰·안전팀 + 외부 전문가(보호관찰·재활 분야)로 구성된 소위원회가 심사한다. 심사 기준: 범죄 유형(특히 대인·성범죄·주거침입 여부), 경과 기간, 재활 이력, 시스템 내 행동 기록.
3. **성범죄·중대 대인범죄 전력**: 일반 가정 배정은 원칙적으로 배제하고 공공형 쉬빌 홈으로 한정한다. 이것은 배제가 아니라 **엔젤 보호와 당사자 보호(무고 리스크 차단)의 양면 조치**다.
4. **단계적 신뢰 회복**: 공공형 홈에서의 체류 기록과 완주 이력이 쌓이면 재심사를 통해 전문 엔젤 → (해당되는 경우) 일반 가정으로 이동 가능. **시스템 안에서의 행동이 과거 기록을 갱신한다.**

### 5.4 재활·사회 복귀 관점의 의미

- 걷기로 코인을 벌어 숙식을 스스로 지불하는 구조는 그 자체가 **자립의 리허설**이다: 노동(걷기) → 소득(코인) → 소비(숙식) → 평판(후기)의 순환을 안전한 환경에서 경험한다.
- 보호관찰소·재활 기관과의 제휴로 "쉬빌 완주"를 사회 복귀 프로그램의 공식 이수 항목으로 인정받는 방안을 추진한다 (미해결 쟁점 8.6).
- 완주한 전력자가 훗날 공공형 쉬빌 홈의 관리 자원봉사자, 나아가 전문 엔젤이 되는 경로를 열어 둔다. **수용받은 사람이 수용하는 사람이 되는 순환**이 이 정책의 최종 목표다.

## 6. 프라이버시와 낙인 방지

### 6.1 대원칙

1. **최소 수집**: 각 레벨에서 필요한 최소한만 수집한다 (GDPR 5조 데이터 최소화, 한국 개인정보보호법 제3조 동일 취지).
2. **목적 구속**: 검증 목적으로 수집한 정보를 매칭·마케팅에 재사용하지 않는다.
3. **분리 저장**: 신원 검증 데이터(신분증), 민감 데이터(위기·전과 기록), 서비스 데이터(매칭·후기)를 물리적/논리적으로 분리하고, 접근 권한을 역할별로 최소화한다.
4. **파기 기한**: 신분증 원본 이미지는 검증 완료 즉시 파기(또는 규제상 보존 의무가 있는 경우만 암호화 격리 보존). 위기·심사 기록은 보존 기한 후 자동 파기.

### 6.2 "결과만 전달, 사유는 비공개" 설계 (핵심)

민감 정보(정신건강·범죄 기록)에 대해 엔젤이 알게 되는 것은 오직 하나다:

> **"이 리스트는 회원님의 수용 조건과 맞습니다 / 맞지 않습니다."**

- 심사·경로 배정의 **결과**(어느 수용처가 가능한가)만 매칭 엔진에 플래그로 반영되고, **사유**는 격리 저장소에 남아 매칭 엔진과 엔젤 양쪽 모두에게 보이지 않는다.
- 조건이 맞지 않는 리스트는 애초에 검색 결과에 나타나지 않으므로, "왜 안 되는지"를 묻는 상황 자체가 생기지 않는다.
- 공공형 쉬빌 홈은 전력자 전용 시설이 아니라 **모두에게 열린 시설**(첫 이용자, 성수기 넘침 수용, 저예산 순례자 포함)로 운영한다. 특정 시설 이용이 곧 낙인이 되는 구조를 원천 차단한다.
- 배지 체계에도 부정 배지는 없다: "검증됨", "완주자", "전문 엔젤"은 있어도 "요주의", "제한됨" 같은 표시는 시스템 어디에도 존재하지 않는다.

### 6.3 GDPR/개인정보보호 체크리스트

| 요건 | 설계 반영 |
|---|---|
| 특수 범주 데이터(건강·전과) 처리 (GDPR 9·10조) | 명시적 동의 + 격리 저장 + 접근 통제. 전과 데이터는 자기 신고분만 보유 |
| 정보 이동권·삭제권 (GDPR 15–17조) | 앱 내 내 데이터 열람·다운로드·삭제 요청 기능. 단, AML 보존 의무 데이터는 예외임을 고지 |
| 자동화 결정에 대한 설명·이의권 (GDPR 22조) | 행동 신호 점수로 인한 경로 조정 시 인간 검토 필수, 당사자 이의 절차 제공 |
| DPIA(영향평가) | 위기 식별·심사 기능은 출시 전 개인정보 영향평가 수행 |
| 국외 이전 | 순례길(유럽)과 운영 법인 소재지가 다를 경우 표준계약조항(SCC) 등 적법 근거 확보 |

## 7. 신고·중재·퇴출 절차

### 7.1 신고 (Report)

- **누가**: 엔젤, 리스트 양방향. 체류 중·후 언제든.
- **채널**: 앱 내 신고 버튼(카테고리: 안전 위협 / 재산 피해 / 규칙 위반 / 우려됨(4.2의 비제재 채널) / 기타), 24시간 전화 라인.
- **긴급 분기**: "지금 위험하다" 선택 시 즉시 현지 응급번호 안내 + 신뢰·안전팀 실시간 대응.
- 신고자 보호: 신고 사실은 피신고자에게 익명 처리, 보복성 후기 차단(2.4의 동시 공개 원칙과 연동).

### 7.2 중재 (Mediation)

1. **1차 — 사실 확인** (48시간 내): 양측 진술, 앱 기록(예약·위치·결제) 대조.
2. **2차 — 조정 제안**: 코인 환불/추가 지불, 사과, 후기 수정 등. 다수 분쟁은 여기서 종결을 목표로 한다.
3. **3차 — 커뮤니티 중재단**: 조정 불복 시, 베테랑 엔젤·완주자로 구성된 중재단(이해관계자 제척)이 판정. 순례 공동체의 자치 원리를 반영.
4. 중재 결과는 당사자에게만 통지하고 공개 프로필에는 반영하지 않는다 (제재 이력의 낙인화 방지).

### 7.3 제재 사다리 (퇴출은 최후 수단)

| 단계 | 조치 | 대상 예시 |
|---|---|---|
| 1 | 경고 + 안내 교육 | 경미한 규칙 위반, 매너 문제 |
| 2 | 기능 제한 (일정 기간 매칭 중단, 공공형 홈만 이용) | 반복 위반, 무단 불참 누적 |
| 3 | 경로 재배정 (일반 가정 → 전문 엔젤/공공형 홈) | 안전 우려가 확인되었으나 악의는 없는 경우 |
| 4 | 계정 정지 (기간제) | 고의적 기만, 재산 피해 |
| 5 | **영구 퇴출** | 폭력·성폭력·중대 범죄 행위 (수사기관 협조 병행) |

- 3단계가 존재하는 것이 이 시스템의 특징이다: **"내보내기 전에 옮길 곳이 있는가"를 항상 먼저 묻는다.**
- 영구 퇴출자의 재가입 방지: 레벨 1 신원 검증 데이터의 해시 대조(원본 미보유 상태에서도 대조 가능하도록 설계).
- 모든 4·5단계 제재에는 이의 신청 절차(14일)를 보장한다.

### 7.4 엔젤에 대한 조치

엔젤도 동일한 사다리를 적용받는다 (리스트 대상 착취·차별적 행위·안전 의무 위반 등). 다만 자원봉사자라는 지위를 고려해, 1–2단계에서는 제재보다 재교육·짝 엔젤(멘토) 연결을 우선한다.

## 맺음말

이 설계의 성패는 기술이 아니라 한 가지 질문에 대한 일관된 답에 달려 있습니다.

> "이 사람을 받을 수 있는가?"가 아니라 **"이 사람을 어디서 받을 것인가?"**

전화번호 하나로 걷기 시작한 사람이, 신분증 하나로 코인을 벌고, 후기가 쌓여 어느 가정의 손님이 되고, 위기가 오면 전문가의 자리로 옮겨졌다가 다시 길로 돌아오는 것 — 그 전 과정에서 단 한 번도 "당신은 안 됩니다"라는 문장을 듣지 않게 하는 것. 그것이 신뢰·안전·포용부가 이 문서로 제안하는 시스템입니다.

**"누구도 배제하지 않되, 모두가 안전한 자리에서 만나게 한다."**
