## 요약 — 판정: **불통과 (RELEASE BLOCKED)**

M4는 파일럿 전 단계임을 감안하되, 지시서가 정한 기준("치명 결함 = 코인 위조·이중 발행 가능 경로는 불통과 사유")에 해당하는 항목이 존재한다. 계보 서명·정준 직렬화·위치 비저장 원칙은 견고하게 구현되어 있으나, (1) `devMode`가 기본값 true이고 운영 진입점(main.ts)이 이를 하드코딩하여 인증 우회·코인 탈취 경로가 기본 노출되며, (2) 무결성 방어선 1선(앱 무결성)이 부재한 상태에서 회원 번호가 기기 키에 암호학적으로 묶여 있지 않아 위조 코인이 로컬 검증을 통과한다. 두 항목 모두 위조/이중발행 경로다.

핵심 사상 준수는 양호하다: SHV 오프체인·USDC 전용(무법정화폐), 좌표 비저장(전수 확인 통과), 거래 승인 엔드포인트 부재(무승인 시스템)는 헌법 제2·9조에 부합한다. 헌법과 상충하는 구현은 발견되지 않았다.

> 조치 현황 (오케스트레이터): C-1은 본 보고 직후 조치 완료(devMode 기본 false화 + 운영 진입점 환경변수 게이팅 + dev 라우트 게이팅). C-2·H 계열은 결정 대기 3번 및 운영 연동과 결부되어 파일럿 착수 전 필수 조치 목록으로 다니엘 쌤에게 보고.

## 심각도별 발견 사항

### 치명 (CRITICAL) — 릴리스 차단

**C-1. devMode 기본값 true + 운영 하드코딩 → 인증 우회·코인 탈취 경로 기본 노출**
- 근거: `server/src/app.ts` `const devMode = options.devMode ?? true;` / `server/src/main.ts` `buildApp({ ..., devMode: true })`.
- devMode에서 열리는 경로들:
  - `/auth/otp`가 `devCode`를 응답으로 반환 → SMS 없이 임의 전화번호로 가입/신원 위장.
  - `/market/escrows/:id/dev-deposit`가 **인증 없이** 에스크로를 DEPOSITED로 전이 → 구매자가 실제 USDC 미납입 상태로 판매자 코인 이전을 완결 = **코인 탈취**.
  - `/limits/flagged` 수동 등재·해제 무인증 → 정상 회원 코인 수령 차단(DoS)·악성 회원 무단 해제(검열/우회).
  - `/leaderboard/enroll` 자동 verified 처리 → 탑 100 기준선 조작 → 인간 한계 상한 우회.
- 권고: devMode 기본값을 false로, 운영 빌드에서 강제 비활성. dev-deposit·flagged 수동 라우트는 프로덕션에서 미등록. → **조치 완료.**

### 높음 (HIGH)

**H-1. 이중지불: 로컬 차단만 존재, 동기화 대조 미구현.** ~~서버 측 중복 코인 사후 대조가 전무.~~ **조치 완료(2026-07-13):** 기회적 동기화 구현 — 지갑이 온라인일 때 코인 지문(코인 ID·계보 요약·주소, 좌표 없음 — `shared/fingerprint.ts`)을 `POST /sync/coins`로 제출하고, 서버가 대조(`server/src/sync.ts`): ① 같은 (코인 ID, 체인 길이)의 소유자 분기 = 이중 사용 → **분기점 지불자를 소명 대기 목록에 자동 등재** ② 회원별 걷기 증명 합산이 일 400/주 3,000 dSHV 초과 = 초과 생성 → 생산자 등재(분할 형제는 proofHash dedup). 등재는 H-3 서명 배포로 전 지갑에 전파되어 신규 수령 보류. 포착 현황은 `/transparency/anomalies`로 익명 공시. 오프라인 분기·분산 초과 생성·dedup 시나리오 테스트로 고정. **잔여(운영·파일럿 항목): 자동 등재 → 검토단 판정 절차 연동, 오프라인 거래 만료·연쇄 지불 한도(소규모 파일럿에서는 불요) 검토.**

**H-2. 서버 발행 개인키 평문 저장.** ~~promo/claim/reward 개인키를 `kv` 테이블에 평문 저장.~~ **조치 완료(2026-07-13):** 발행 개인키(promo/claim/reward/membership-root)를 환경변수 KEK(`SHVIL_KEK`)로 봉인(XChaCha20-Poly1305)해 kv에 저장 — `server/src/keystore.ts`. **H-3. 신뢰 루트·소명 목록·코스 데이터 미서명 + 평문 HTTP.** ~~`/keys`·`/limits/flagged`·`/courses`가 서명 없이 배포.~~ **조치 완료(2026-07-13):** 세 배포 엔드포인트 응답에 배포 서명(`_sig`, `shared/distribution.ts`) 부착(배포 개인키는 H-2 keystore로 봉인), 지갑은 배포 공개키를 **TOFU 핀**으로 고정 후 모든 배포를 검증(`wallet/distributionGuard.ts`) — 실패 시 기존 캐시 유지·갱신 거부. 발행 키 교체·소명 목록 조작·코스 주입이 캐시에 닿지 않음을 3계층(코어·서버·지갑) 테스트로 고정. **잔여(운영 항목): 전송 계층 TLS·인증서 피닝(애플리케이션 서명과 독립적 이중 방어), 최초 수신(TOFU 이전) 창은 앱 배포판에 배포 공개키 사전 내장으로 폐쇄.**

**H-4. 전화번호 해시의 레인보우 테이블 취약.** `sha256("shvil-phone|" + digits)` — 페퍼 없음. DB 유출 시 전수 대입 역산. 권고: 서버 비밀 키 HMAC 또는 Argon2/scrypt.

## 릴리스 전 필수 조치 (차단 해제 조건)

1. `devMode` 기본 false화 + 운영 빌드에서 dev 라우트 완전 제외. dev-deposit 인증. (C-1) → **조치 완료**
2. 앱 무결성 실토큰을 민팅 필수로, 회원 번호↔기기 키 서버 서명 증서 결속. (C-2)
3. 서버 발행 개인키 KMS/봉인 저장, 키 회전. (H-2)
4. 신뢰 발행 키 목록·소명 목록·코스 데이터 서명 배포 + TLS·인증서 피닝. (H-3)
5. 전화번호 keyed-HMAC, 이메일 실검증, OTP crypto RNG + 재시도 잠금. (H-4, M-1, M-5)

## 파일럿 운영 전제 조건

- 기회적 동기화 기반 사후 이중사용·초과생성 탐지 + 투명성 대시보드 자동 포착 최소 가동(H-1 완충). 없으면 소규모 신뢰 그룹 한정 + 오프라인 거래 만료·연쇄 지불 한도.
- 발행 총량(등록·첫접대·클레임·격려) 실시간 공시·쿼터 강제(M-6).
- 실 SMS/이메일 연동 완료 전 공개 가입 불가.
- 니모닉 복구 미구현 명시 또는 파일럿 전 구현.

## 헌법 준수 확인

위치 비저장, 무승인 거래(승인 엔드포인트 부재 확인), SHV 오프체인·USDC 마켓 전용, 발행 투명성 공시는 코드 수준에서 준수된다. 마켓 수수료 2.5%는 운영 재원이며 공시되어 제2조와 충돌하지 않는다. 헌법과 상충하여 보류·보고할 요구 사항은 발견되지 않았다.
