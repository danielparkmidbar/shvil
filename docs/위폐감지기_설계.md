# 위폐 감지기 — 일련번호와 시간 거리 (M16)

> 다니엘 쌤 2026-07-26:
> **"같은 지갑에서 형성될 수 있는 코인은 형성에 물리적 시간이 필요하다. 프로그램을
> 통해 코인을 복제하면 각각의 코인 형성 간의 시간 거리를 부여할 수 없다. 화폐에
> 일련 번호가 있듯 코인에도 일련 번호가 있는데, 위폐 감지기 기능처럼 이 코인들이
> 정상적으로 만들어진 것인지 복제된 것인지 판별할 수 있다. 쉬빌 코인 사이트에
> 코인을 업로드하면 위조 쉬빌 코인인지 아닌지 확인할 수 있는 방식으로 디자인해보자."**

## 1. 왜 이 통찰이 중요한가

서명 검증(verifyCoin)은 "이 코인이 **어떤 키로** 서명됐는가"만 답한다. 변조 앱이
자기 기기 키로 조작된 걷기 증명을 서명하면 **서명은 완벽히 유효하다.** 실제로 이번
세션에 발견된 스팟 예치 무제한 발행구가 정확히 그 구멍이었다 — 서명은 진짜인데
내용이 거짓인 코인.

다니엘 쌤의 통찰은 방어의 축을 옮긴다: **위조자는 서명을 위조할 필요가 없지만,
시간은 위조할 수 없다.** 지폐 위폐 감지기가 종이의 물성(자외선 반응·자기 잉크)을
보듯, 쉬빌 위폐 감지기는 코인의 물성 — 거리·걸음·시간이 서로를 반증하는 구조 —
을 본다.

이것은 주권적 화폐 연구("개발자인 나도 통제할 수 없어야 한다")와 정확히 이어진다:
판정이 **순수 함수**라서 서버가 없어도, 쉬빌 서버가 사라져도, 누구든 같은 코드를
돌려 같은 답을 얻는다. 개발자가 판정을 바꿀 방법이 없다.

## 2. 일련번호 — `packages/shared/src/serial.ts`

형식: **`SHV-XXXXX-XXXXX-XXXXX-C`** (Crockford Base32 15자 + 체크 문자)

★핵심 결정: **일련번호는 새 필드가 아니다.** coin.id(계보 해시)에서 유도되는 표시
형식일 뿐이다.

| 대안 | 문제 |
|---|---|
| 코인 구조에 번호 필드 추가 | 위조자가 고쳐 쓸 수 있고, 기존 코인 전부 비호환 |
| 서버가 번호 발급 | 제9조 위반 — 서버가 죽으면 번호도 죽는다 |
| **계보 해시에서 유도 (채택)** | **계보가 바뀌면 번호가 바뀐다 — 번호 자체가 무결성 검사** |

- Crockford 알파벳(I·L·O·U 제외): 전화로 불러 주거나 손으로 옮겨 적을 때 1/I/l,
  0/O 혼동이 없다. 입력 정규화가 I→1, O→0, 소문자, 하이픈 생략을 흡수한다.
- 체크 문자는 **오타 검출용**이지 위조 방어가 아니다. 진위는 코인 전체가 증언한다.
- 75비트 — 10억 코인 규모에서도 충돌 무시 가능.

## 3. 위폐 감지기 — `packages/shared/src/authenticity.ts`

### 판정 4단계

| 판정 | 뜻 |
|---|---|
| `FORGED` | 물리적으로 불가능한 것이 코인 안에 있다. 반박 불가. |
| `SUSPECT` | 결정적 위반은 없지만 사람의 걷기로 보기 어려운 정황 **2건 이상** |
| `AUTHENTIC` | 위조 근거 없음 (**"진짜 증명"이 아니라 "모순 없음"** — 요약문이 명시) |
| `INCONCLUSIVE` | 검사할 재료 없음 |

### 검사 축 ① — 코인 한 장 안의 물리 (결정적 = FATAL)

걷기 증명은 거리·걸음·시간·발행액을 한 몸에 품고 있어 서로를 반증한다:

- **TIME_WINDOW**: 끝이 시작보다 앞서거나, 정산 시각이 미래(시계 조작 상한 우회)
- **SPEED_LIMIT**: 평균 속도 > 35 km/h (자전거 상한 — 코인에 이동 수단이 안 새겨지므로
  **가장 관대한 상한**을 쓴다. 도보 상한으로 재면 자전거 이용자가 억울해진다)
- **STRIDE**: 보폭 하한 미만 = 걸음 수 부풀리기 (상한 초과는 자전거일 수 있어 정황만)
- **CADENCE**: 평균 케이던스 > 140 spm — 휴식이 섞이면 평균은 **낮아지므로**
  평균 초과는 기계적 반복이다 (하한은 휴식 때문에 검사 불가)
- **MINT_RATE**: 발행액 > 거리 × 최대 요율(난이도 ×4.0) — **스팟 무제한 발행구가
  걸리는 지점**
- **DAILY_CAP / BREAKDOWN_DATES**: 일일 400 dSHV 초과 / 걷지 않은 날짜의 발행 귀속

### 검사 축 ② — ★코인들 사이의 시간 거리 (다니엘 쌤 통찰의 핵심)

- **WINDOW_OVERLAP**: 같은 회원의 두 걷기 창이 겹친다. 잠정 원장은 정산마다
  비워지므로 정상 코인의 창은 절대 겹치지 않는다. 겹침 = 원장이 둘 = 복제.
- **TIME_BUDGET**: 코인들이 주장하는 총 거리를 이동하는 데 필요한 최소 시간이
  실제로 흐른 시간(첫 시작~마지막 정산)보다 크다. **코인은 복제할 수 있어도
  코인 사이의 시간은 만들어 넣을 수 없다.**
- **SENSOR_DUPLICATE**: 같은 회원의 다른 증명이 같은 센서 요약(시작 ms 포함) — 복사.
  (다른 회원 간 일치는 함께 걸었을 수 있어 정황만 — 관대한 쪽으로)
- **COIN_DUPLICATE**: 같은 코인이 다른 이전 상태로 두 번 제출 — 이중 지불.

### 검사 축 ③ — 통계 (SIGNAL — **절대 단독으로 위조 판정하지 않는다**)

간격 균일성(CV<2%) · 값 균일성(거리·걸음 CV<1%) · 시각 격자(전부 ms 000) ·
몰림(24h에 정산 20건 초과). 표본 5개 미만이면 아예 돌리지 않는다.

★가장 중요한 불변식(테스트로 고정): **통계 신호는 몇 개가 쌓여도 FORGED가 되지
않는다.** 정직한 사람을 위폐범으로 지목하는 것이 위조를 놓치는 것보다 나쁘다(제3조).

### 정직화 장치 (제3조)

- AUTHENTIC 요약: "위조의 근거를 찾지 못했습니다 … **진짜임을 증명한 것은 아닙니다**"
- `notes[]`: 검사 못 한 범위를 명시 (발행 키 목록 없음 → GRANT 발행자 신원 미확인,
  루트 키 없음 → 무결성 증서 미확인, 코인 1장 → 시간 거리 검사 불가)
- 신뢰 키 목록이 없는 환경에서 UNTRUSTED_ISSUER를 FATAL로 삼지 않는다 —
  정직한 보너스 코인을 위폐로 만들지 않기 위해서다.

## 4. 사이트 — shvilist.org/verify

`apps/web-list/src/app/verify/page.tsx` (4개 언어 내비에 "위폐 감지기" 추가):

- 붙여넣기 또는 파일 업로드 → `parseCheckerInput` → `checkAuthenticity` → 리포트
- 받는 형식: 코인 JSON / 코인 배열 / `{coins:[...]}` (지갑 내보내기) / `SHV1.` 지불 QR
- **암호화 백업 blob은 받지 않는다** — 백업 키를 사이트에 넣게 유도하면 안 된다.
- ★검사는 **전부 브라우저 안에서** 실행된다. 코인은 어디로도 전송되지 않는다.
  서버 API가 없다 — Cloudflare 정적 배포 그대로 동작하고, 쉬빌 서버가 죽어도 동작한다.
- 판정 상세 문장은 코어가 한국어로 생성한다 (비한국어 로케일에는 안내 문구 표시).

## 6. 한계 (정직화)

- **완벽히 흉내 낸 위조는 못 잡는다.** 물리적으로 그럴듯한 값을 사람의 들쭉날쭉함까지
  흉내 내 찍으면 이 감지기는 통과한다. 그러나 그 비용이 급등한다: 하루 40 SHV 상한 +
  창 겹침 금지 때문에 **위조 수익이 실제로 걸을 때와 같은 속도로만 쌓인다** —
  복제의 경제적 이점이 사라진다. 이것이 이 설계의 진짜 방어다.
- 시간 거리 검사는 **같은 회원의 코인 여러 장**이 있어야 강해진다. 코인 한 장은
  물리 정합만 본다. 그래서 사이트가 "지갑 전체 업로드"를 권한다.
- 통계 임계값(CV 2%/1% 등)은 초기 보수값이다 — 실사용 데이터가 쌓이면 조정한다.
  보수적일수록 억울한 SUSPECT가 없다는 원칙은 유지한다.
