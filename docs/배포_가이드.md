# 배포 가이드 — 웹(Cloudflare Pages) + 서버(Render 무료)

대상: 다니엘 쌤 · 목적: 닫힌 시험용 배포. **실제 업로드는 다니엘 쌤이 수행**한다.

시스템은 3덩어리다: **shvilangel.org**(정적 웹) · **shvilist.org**(정적 웹) · **디렉토리 서버**(Node).
웹 두 사이트는 디렉토리 서버 API를 소비한다 — **서버를 먼저 띄우고 그 주소를 웹 빌드에 넣는다.**

---

## 0. 준비: GitHub에 저장소 올리기

Cloudflare Pages·Render 둘 다 GitHub 저장소를 연결하는 방식이 가장 쉽다.

```
cd shvil-dev
git remote add origin https://github.com/<계정>/shvil-dev.git
git push -u origin master
```

(비공개 저장소여도 됨. Cloudflare·Render 모두 비공개 연결 지원.)

---

## 1. 먼저 서버 — Render 무료

1. https://render.com 가입 → **New +** → **Blueprint** 선택.
2. 저장소 연결 → 루트의 `render.yaml`을 Render가 자동 인식(서비스 이름 `shvil-directory`).
   - `SHVIL_KEK`은 Render가 안전한 랜덤 값을 자동 생성한다(보안 감사 H-2).
   - `SHVIL_DEV_MODE=1`로 설정되어 있다(닫힌 시험용 — 아래 ⚠ 참고).
3. 배포 완료 후 URL 확인: `https://shvil-directory-XXXX.onrender.com`
4. 동작 확인 — 브라우저나 터미널에서:
   ```
   https://shvil-directory-XXXX.onrender.com/transparency/promo
   → {"registrationIssued":0,...} 가 나오면 성공
   ```
   (무료 티어는 15분 유휴 후 슬립 → **첫 요청이 ~30초 지연**. 정상이다.)

**⚠ 무료 티어 데이터 초기화:** Render 무료는 디스크가 임시(ephemeral)라 **재시작·재배포 때 SQLite가 초기화**된다. 닫힌 시험엔 충분. 지속이 필요하면 Render 유료 디스크나 외부 DB로.

## 2. 웹 두 사이트 — Cloudflare Pages

두 사이트를 **각각** Pages 프로젝트로 만든다. 설정은 동일하고 디렉토리만 다르다.

### shvilangel.org

1. https://dash.cloudflare.com → **Workers & Pages** → **Create** → **Pages** → **Connect to Git** → 저장소 선택.
2. 빌드 설정:
   | 항목 | 값 |
   |---|---|
   | Framework preset | None (또는 Next.js Static HTML Export) |
   | Build command | `npm install && npm run build -w @shvil/web-angel` |
   | Build output directory | `apps/web-angel/out` |
   | Root directory | (비움 — 모노레포 루트) |
3. **환경 변수** (Settings → Environment variables) — 빌드에 서버 주소를 인라인해야 한다:
   ```
   NEXT_PUBLIC_DIRECTORY_URL = https://shvil-directory-XXXX.onrender.com
   ```
   (1번에서 받은 Render 서버 URL. 이 값이 빌드 시 웹에 박힌다 — 서버 URL이 바뀌면 재빌드.)
4. 배포 → `https://shvilangel-XXXX.pages.dev` 접속.

### shvilist.org

같은 절차, 값만 교체:
- Build command: `npm install && npm run build -w @shvil/web-list`
- Build output directory: `apps/web-list/out`
- 환경 변수: 동일한 `NEXT_PUBLIC_DIRECTORY_URL`

### 커스텀 도메인 (선택)

각 Pages 프로젝트 → Custom domains → `shvilangel.org` / `shvilist.org` 연결(도메인을 Cloudflare에 두면 자동).

## 3. 확인

- 웹 접속 → 우상단 언어 스위처로 **עברית(히브리어) 선택 → 전체 레이아웃이 우→좌(RTL)로 뒤집히는지**.
- 엔젤 지도·마켓·투명성 페이지가 서버 데이터를 불러오는지(서버가 슬립이면 첫 로드가 느릴 수 있음).
- 서버가 비어 있으면 "아직 없음"으로 표시된다(정상 — 앱으로 엔젤을 등록해야 채워짐).

---

## ⚠ 지금 배포의 한계 (파일럿 착수 전)

1. **`SHVIL_DEV_MODE=1`은 닫힌 시험 전용이다.** 이 모드는 가입 OTP 코드를 응답에 노출한다(실 SMS 미연동 때문). 아는 사람끼리 시험할 때만. **공개 홍보 전에는 `0`으로 바꾸고 실 SMS/이메일을 연동**해야 한다(보안 감사 C-1·M-1·M-5).
2. **실제 가입→걷기→지불**은 웹이 아니라 **폰 앱**에서 일어난다. 웹은 지도·마켓·투명성 열람용이다. 앱(apps/wallet)은 Expo Go 또는 개발 빌드로 폰에 올려야 한다(별도 작업).
3. 파일럿 필수 조치의 운영 항목(실 Play Integrity 토큰·TLS 인증서 피닝·KMS)은 공개 운영 전 마무리 대상이다(`docs/보안감사_M4.md`).

## 요약 순서

```
① git push (GitHub)
② Render Blueprint 배포 → 서버 URL 확보
③ Cloudflare Pages ×2 (web-angel / web-list), NEXT_PUBLIC_DIRECTORY_URL에 서버 URL
④ 접속 확인 (RTL·데이터 로드)
```
