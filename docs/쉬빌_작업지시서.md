- 관리: 오케스트레이터
- 대상: Claude Code 개발 세션 (이 문서를 레포 루트에 두고 CLAUDE.md에서 링크할 것)

## 0. 시스템의 핵심 사상 (변경 금지 — 모든 구현 판단의 기준)

1. **코인은 각 사용자의 스마트폰에서 생성된다.** 서버가 발행하지 않는다. 걷기를 마치면 위치 기반으로 본인 휴대폰 안에서 코인이 형성된다. 스스로 기록하고 스스로 인증한다.
2. **중앙 대조 원장이 없다.** 거래를 승인하는 서버가 없다. 실시간으로 수십만 건이 거래되어도 거래별 승인이 필요 없다. 두 기기 간 서명 교환으로 거래는 그 자리에서 완결된다.
3. **신뢰 기반으로 돌아간다.** 이 메커니즘을 깨는 방법은 소프트웨어 해킹뿐이다. 따라서 방어는 거래 감시가 아니라 **앱 무결성**(변조 불가), **코인 계보 서명**(위조 불가), 그리고 **회원 번호 + 인간 한계 프로파일**(한 사람이 하루에 걸을 수 있는 걸음에는 신체적 상한이 있으므로 특정 회원의 무한 복제는 현실적으로 불가능)에 집중한다. 신원은 최소로 — 의무는 전화번호·이메일 실존 확인뿐, 나머지 정보는 제공량도 공개 범위도 사용자가 결정한다.
4. **지갑은 동시에 메신저다.** 엔젤과 리스트는 지갑 안에서 대화한다.
5. **생성 요율은 걸음의 자리에 따라 다르다.** 이것은 순례길로 등재된 코스를 걷는 순례자를 위한 화폐다. 등록 코스 위의 걸음만 기준 요율(1km = 1 SHV)로 생성된다. 순례 중 코스를 벗어난 걸음은 감액 요율로 적게 생성되고, 일상의 걸음은 1/1,000~1/10,000의 미세 요율로만 생성된다. 뛰는 속도 이상의 이동, 자동차·교통수단 이동은 어디서든 카운트되지 않는다. 예외: 코스를 벗어나 등록된 엔젤의 집으로 가는 이동은 기준 요율로 잠정 카운트한다 — 단, 그 엔젤에게서 코인을 사용해야 확정된다. 그리고 **난이도가 다르면 요율도 다르다** — 에베레스트 코스처럼 위로 갈수록 힘들어져 하루에 이동할 수 있는 거리가 줄어드는 구간은 난이도 계수가 붙어 적게 걸어도 많이 생성된다. 기준은 언제나 "하루의 성실한 걸음 = 약 20 SHV"다.
6. **정산은 사용 또는 본인의 선언으로만 이루어진다.** 사용하지 않고 계속 걸으면 잠정 누적으로 계속 쌓인다. 어떤 형태로든 사용하는 순간 그 구간이 정산되고 거기서 새 구간이 시작된다. 트레킹을 중도에 끝낼 것 같으면 **그 지점에서 본인이 정산해야 한다**(앱의 "여기서 정산" 기능). 시작만 있고 순례길 위의 생성이 없으면 아무것도 만들어지지 않는다 — **자동 생성·자동 정산은 없다.**
7. **호혜 모델 (Airbnb의 반대).** 에어비앤비는 돈을 받고 집을 빌려주는 모델이다. 쉬빌은 "내 집을 내어주면, 나도 다른 곳에서 다른 사람의 집을 이용할 수 있다"는 모델이다. 엔젤은 (서비스 확장을 전제로) 다른 국가에서도 코인을 사용할 수 있다.
8. **여행하지 않는 엔젤은 코인을 판다.** shvilangel.org 마켓에서 무정가 리스팅 → 구매자가 가격 제시 → 엔젤이 승인 → 달러 스테이블코인으로 결제된다.
9. **모든 지갑은 협약된 달러 스테이블코인 지갑을 겸한다.**
10. **위치 기반이지만 위치 추적이 아니다 (사생활 보호).** 위치는 A→B 이동을 판별하는 그 순간에만 쓰이고 즉시 버려진다. 코인이 생성되고 나면 남는 정보는 **이동 거리뿐**이다. 위치 정보·이동 경로는 어디에도 기록하지 않는다 — 폰에도, 서버에도.

확정 경제 파라미터: 등록 코스 위 도보 1km = 1 SHV (기준 요율) · 코스 이탈 걸음 감액 요율(제안 1/10, 확정 대기) · 일상 걸음 미세 요율 1/1,000~1/10,000 (확정 대기) · 1인 1일 상한 40 SHV · 권장 가격 잠자리 10 / 식사 5 / 샤워 3 / 풀 패키지 18 SHV · 엔젤 등록 보너스(등록 20 + 첫 접대 30 SHV, 기간·수량 한정).

## 1. 전체 아키텍처

```
[쉬빌 지갑 앱]  (하나의 앱, 두 모드)
 ├─ 리스트 모드: 걷기 기록 → 온디바이스 민팅 → QR 지불
 ├─ 엔젤 모드: 서비스 등록 → 수령 → 마켓 판매
 ├─ 메신저 (엔젤↔리스트 채팅)
 └─ 스테이블코인 지갑 (협약 코인, 예: USDC)

[디렉토리 서버]  ※ 거래 승인 기능 없음 — 아래 4가지만 담당
 ├─ 엔젤 디렉토리(지도·프로필·서비스 정보)
 ├─ 메신저 릴레이(종단간 암호화, 서버는 중계만)
 ├─ 마켓(리스팅·가격 제시·에스크로 상태)
 └─ 인증 경로 데이터 배포(트레일 폴리라인·엔젤 포인트 좌표·오프라인 지도 팩)

[shvilangel.org]  엔젤의 집 — 지도, 지갑 다운로드, 코인 마켓
[shvilist.org]   리스트의 집 — 여정 기록·자기 인증 공개 페이지
[스테이블코인 체인]  마켓 결제 전용 (SHV 자체는 온체인 아님)
```

핵심 선언: **SHV 코인 자체는 블록체인 위에 있지 않다.** 코인은 서명된 데이터 구조로서 각자의 폰에 존재하고 폰과 폰 사이를 이동한다. 블록체인(스테이블코인)은 마켓에서 현금 가치와 교환할 때만 등장한다.

## 2. 코인 코어 설계 (WP-0, 최우선 작업 패키지)

### 2.1 키와 신원 — 회원 번호 체계

- 최초 실행 시 기기의 보안 영역(iOS Secure Enclave / Android StrongBox)에 키쌍 생성. 공개키 해시가 지갑 주소.
- **회원 번호**: 가입 시 고유 회원 번호가 발급되고, 이후 그 회원이 생성하는 **모든 코인에 회원 번호가 새겨진다**. 코인은 익명 코인이 아니라 "누구의 걸음에서 태어났는지"를 아는 코인이다. 이것이 3장의 무한 복제 방지의 뿌리가 된다.
- **의무 정보는 둘뿐**: 전화번호(OTP 인증)와 이메일(실존 확인). 시스템의 안정적 운영을 위한 최소 정보만 요구한다.
- **선택 정보는 사용자가 결정**: 실명, 사진, 국적, 순례 이력, 자기소개 등은 제공하고 싶은 만큼만. 어떤 항목을 시스템에만 제공하고 어떤 항목을 공개할지도 사용자가 항목별로 결정한다. UI는 "정보를 많이 공개할수록 엔젤들이 받아들이기 쉽습니다"를 명시하여 자발적 공개를 유도한다 — 강제가 아니라 신뢰의 거래.
- 키 백업: 니모닉 문구(12단어) — 폰 분실 시 확정 코인 복구 경로. 백업 강제 아님, 강력 권고 UI.

### 2.2 연속 생성 — 만보기 모델 (온디바이스 민팅)

- **생성 조건은 "등록된 코스 위에서의 걷기"다.** 앱이 백그라운드에서 만보기처럼 상시 동작하며, 등록 코스의 회랑 안에서 걷는 동안 거리·걸음 수·SHV가 실시간 누적된다. 별도의 시작/종료 버튼 없이도 동작하는 것이 기본(수동 모드는 옵션).
- **코스 데이터 내장**: 쉬빌 이스라엘을 포함한 대표 트레킹·순례 코스의 GPS 폴리라인 좌표를 앱에 내장한다(오프라인 동작 필수). 코스 목록의 원본은 shvilist.org 코스 등록부이며, 앱은 주기적으로 갱신분을 내려받는다.
- **코스 판정**: 현재 위치를 내장 폴리라인과 대조해 회랑(코스 좌우 일정 폭) 안/밖을 판별한다. 회랑 밖 이동은 카운트하지 않는다. 판정은 휘발성 메모리에서만 이루어지고 좌표는 즉시 폐기(위치 비저장 원칙 유지). 계보에는 좌표 대신 **코스 ID**(예: "쉬빌 이스라엘")만 남는다.
- **엔젤 우회 예외**: 코스를 벗어나되 목적지가 등록된 엔젤 포인트인 이동은 잠정 카운트한다. 이 우회 거리는 **그 엔젤에게 코인을 사용(지불)하는 순간에만 확정**되고, 사용 없이 지나가면 소멸한다. (제안: 우회 인정 한도 편도 5km — 결정 대기)
- **사용자 코스 등록**: 누구나 shvilist.org에 새 코스를 제안·등록할 수 있다. 같은 코스를 **100명 이상**이 이런 방식으로 등록(완주 기록 제출)하면 공식 인정 코스로 승격되어 앱 코스 데이터에 포함된다. 그 전까지는 후보 코스로 표시되며 코인 생성은 되지 않는다.
- **걷기 판별 필터** (전부 온디바이스):
  - 속도 프로파일: 보행 범위만 인정. **뛰는 속도 이상은 카운트하지 않는다.** 자동차·버스 등 교통수단 이동 자동 제외.
  - 걸음 센서 교차 검증: GPS 거리와 가속도계 걸음 파형이 일치해야 인정 (만보기처럼 실제로 걸어야 생성).
  - **사용자 패턴 학습 모델**: 쉬빌 이스라엘 코스에서 정상 사용자의 실제 이동 패턴 데이터를 학습한 이상 탐지 모델(온디바이스 경량 모델)로 비정상 이동(구간 순간이동, 기계적 반복 파형, 차량 혼입)을 걸러낸다. 모델은 익명 동의 데이터로 주기 갱신·배포.
- **위치 비저장 원칙 (필수 구현)**: GPS 좌표는 걷기 판별을 위한 휘발성 버퍼(메모리)에서만 사용하고, 거리 계산이 끝나는 즉시 폐기한다. 디스크에 좌표·궤적을 쓰지 않는다. 패턴 학습 모델의 입력도 속도·보폭·파형 등 파생 지표만 사용하며 좌표는 사용하지 않는다. 코인·증명·백업·통계 어디에도 위치 정보가 포함되지 않는다.
- **생성 요율 (3단계 + 난이도 계수)**:

| 걸음의 자리 | 요율 |
|---|---|
| 등록 코스 회랑 안 | 1km = 1 SHV × 구간 난이도 계수 |
| 코스 이탈 (순례 중 벗어난 걸음) | 감액 요율 (제안 1/10 — 확정 대기) |
| 일상 걸음 (코스 밖 생활권) | 미세 요율 1/1,000 또는 1/10,000 (확정 대기) |
| 엔젤 우회 (등록 엔젤 집으로) | 기준 요율 잠정 — 해당 엔젤에게 사용 시 확정 |

- **난이도 계수**: 코스 등록부가 구간별 계수를 갖는다(평지 ×1.0 ~ 고산·급경사 최대 ×4.0 제안). 계수는 "그 구간에서 성실한 하루 걸음이 약 20 SHV가 되도록" 보정한다 — 에베레스트 트레킹처럼 하루 8km밖에 못 가는 구간이면 ×2.5로 하루치가 성립한다. 계수는 코스 등록 시 표고 데이터로 자동 산출 + 커뮤니티 검증.
- 민팅 계산: 0.1 SHV 단위 내림, 1일 40 SHV 상한(요율·계수 적용 후 총액 기준).
- **누적과 정산의 분리**:
  - 걷는 동안 SHV는 **잠정 누적(pending)** 상태로 계속 쌓인다. 사용하지 않으면 며칠이고 계속 생성된다.
  - **어떤 형태로든 사용하는 순간**(엔젤 지불, 마켓 리스팅 등) 마지막 정산 이후의 걷기 구간이 `WalkSegmentProof`(구간 요약 + 기기 서명)로 확정·정산되어 코인이 되고, 그 자리에서 새 구간이 시작된다.
  - **수동 정산 ("여기서 정산")**: 트레킹을 중도에 끝낼 것 같으면 사용자가 그 지점에서 직접 정산해야 한다. 앱은 코스 이탈이 장시간 지속되면 "순례를 마치셨나요? 여기서 정산하세요" 알림으로 안내한다.
  - **자동 생성·자동 정산 없음**: 시작만 있고 순례길 위의 생성이 없으면 아무것도 만들어지지 않는다. 정산되지 않은 잠정 누적은 폰 분실 시 복구를 보장하지 않는다(니모닉 백업은 확정 코인만 복구).
- 산출물: `WalkSegmentProof` — 구간 거리·걸음 수·기간·센서 요약 해시에 기기 키로 서명한 구조체. 민팅된 코인은 이 증명을 계보(provenance)로 품는다.
- **자기 인증**: 검증 서버 없음. 앱이 스스로 규칙을 적용해 민팅한다. 규칙의 신뢰성은 3장의 앱 무결성이 보장한다.
- 걸음 수 표시: 홈 화면에 오늘/누적 걸음 수를 상시 표시한다 (만보기 기능 겸용).

### 2.3 코인 데이터 구조와 이전(무승인 거래)

```
Coin {
  id, amount,
  memberId,          // 생성자 회원 번호 — 모든 코인에 새겨짐
  provenance: WalkSegmentProof 서명 | AngelBonus 서명 | Market 구매 기록 | CommunityClaim 승인 기록 | CommunityReward 격려 보상,
  transferChain: [ {from, to, timestamp, 양측 서명} ... ]
}
```

- 지불: QR 왕복 — 수령자(엔젤)가 청구 QR 제시 → 지불자(리스트)가 스캔·서명 → 지불 확인 QR을 엔젤이 역스캔 → 완결. **서버 개입 0회, 통신 불요, 승인 불요.** 광야 한복판에서도 동작한다.
- 수령 기기는 코인의 계보(민팅 서명 + 이전 체인)를 **로컬에서 즉시 검증**한다(밀리초 단위, 승인이 아니라 위조 검사). 서명이 유효하면 끝.
- 기회적 동기화: 폰이 온라인이 될 때 자기 지갑 상태를 암호화 백업. 목적은 승인이 아니라 (a) 폰 분실 복구, (b) 사후 이상 탐지 통계.

### 2.4 엔젤 보너스 민팅

- 엔젤 등록 완료(전화 인증 + 지도 등록 + 서비스 입력) 시 20 SHV, 첫 접대(리스트의 지불 수령으로 자동 확인) 시 30 SHV를 엔젤 폰에서 민팅. 프로모션 서명 키는 기간·수량 한정으로 발급.

### 2.5 클레임 구제 민팅 (커뮤니티 인정 발행)

실제로 걸었는데 앱을 깜빡 켜지 않았거나 오류로 생성되지 않은 경우의 구제 절차. **하루(24시간) 안에 일어난 실수에 한한다.**

1. 사용자가 shvilist.org 클레임 게시판에 트레킹 정보(코스·구간·날짜·거리)와 사진들을 올린다.
2. 다른 사용자들이 게시물을 검토하고 "인정" 투표를 한다. **기준 인원 이상**(제안 5명 — 확정 대기)이 인정하면 승인.
3. 승인되면 사이트가 자료에 근거해 해당 SHV를 산정(해당 구간 요율·난이도 계수 적용, 1일 40 상한 준수)하고, **사이트의 클레임 발행 키로 민팅하여 클레임 사용자의 지갑으로 전송**한다. 코인 계보에는 CommunityClaim(게시물 링크 해시 + 인정자 수)이 남는다.
4. 남용 방지: 걷기 발생 후 24시간 이내 접수만 유효, 1인당 클레임 빈도 한도(제안 월 2회 — 확정 대기), 인정 투표자는 본인 확인(레벨 1) 사용자로 한정, 클레임 발행 총량은 투명성 페이지에 공시.

### 2.6 격려 코인 (완주 인증 공유 보상 — 초기 커뮤니티 활성화)

정보를 나누는 사람이 커뮤니티를 만든다. 완주 인증과 트레킹 데이터 공유에 게시판이 격려 코인을 발행해 송금한다.

- 대상: shvilist.org 게시판에 **완주 인증 사진 + 트레킹 데이터**(코스·구간별 기록·소요일 등)를 올린 사용자.
- 발행: 게시물이 등록 요건(사진 + 데이터 완비)을 충족하면 사이트가 격려 보상 키로 민팅하여 게시자 지갑으로 자동 송금. 계보에는 CommunityReward(게시물 해시)가 남는다.
- 보상액 제안(확정 대기): 코스 완주 인증 10 SHV, 구간 인증 3 SHV. 같은 코스 중복 보상 없음(1인 1코스 1회).
- 한정 운영: 프로모션 기간·총량을 정해 공시하고(엔젤 등록 보너스와 동일 원칙), 초기 활성화 목적 달성 후 축소·종료할 수 있다. 발행 현황은 투명성 페이지에 공시.
- 부수 효과: 이렇게 모인 완주 데이터·사진은 후보 코스의 100명 승격 심사와 클레임 인정 투표의 참고 자료가 된다 — 격려 코인이 커뮤니티의 검증 능력 자체를 키운다.

## 3. 무결성 방어선 (승인 없는 시스템의 유일한 방어 — 필수 구현)

거래를 감시하지 않는 대신, 다음 세 겹으로 "해킹만" 막는다.

1. **앱 무결성 증명**: Google Play Integrity / Apple App Attest를 민팅 시점에 요구. 변조된 앱·에뮬레이터·루팅 기기에서는 JourneyProof에 유효한 증명이 붙지 않아, 그 코인은 수령 기기의 로컬 검증에서 거부된다.
2. **계보 서명**: 모든 코인은 민팅 증명부터 현재까지 서명 체인을 갖는다. 서명 없는 코인은 존재할 수 없다. 위조는 키 탈취 없이 불가능.
3. **인간 한계 프로파일 검증 (무한 복제의 구조적 차단)**: 코인 생성이 회원 번호에 묶여 있으므로, 한 회원이 만들 수 있는 코인에는 인간의 신체가 정한 자연 상한이 있다 — 하루·특정 기간에 걸을 수 있는 걸음 수, 코스 난이도별 하루 이동 가능 거리, 그리고 사용자 그룹의 평균치. 수신 지갑은 코인을 받을 때 계보의 회원 번호·날짜·거리를 로컬에서 대조하여 **"이 회원이 이 기간에 이만큼 걸었다는 것이 인간적으로 가능한가"**를 검사한다(예: 같은 회원 번호로 같은 날 40 SHV 초과, 또는 한 주에 300 SHV 같은 물리적 불가능치는 즉시 거부). 코스 난이도·그룹 평균 기반 개연성 모델은 검증 엔진에 내장하고 주기 갱신한다. 특정 회원의 무한 복제는 이 구조에서 현실적으로 불가능하다 — **이것이 중앙 승인 없는 시스템의 담보다.**
   - **검증된 탑 100 기준선**: 개연성 모델의 상한은 이론값이 아니라 실측값으로 잡는다. 전문 산악인·전문 트레커·짐을 나르는 포터 등 검증된 인물들의 **지역별 상위 100 리스트**를 본인 동의하에 공개하고(트레킹 거리·생성 코인 총량만 — 위치 없음), 이들의 기록이 그 지역·코스에서 인간이 도달한 실제 상한선이 된다. **이 기준선을 추월하는 생성자는 자동 포착**되어 검토 절차에 회부된다. 세계 최고의 포터보다 더 걸었다고 주장하는 코인은 존재 자체가 증거다.
4. **커뮤니티 자체 모니터링**: 중앙 결제 시스템은 없지만, 생성되고 거래되는 양상은 커뮤니티가 스스로 지켜본다. 동기화된 통계를 공개 대시보드(shvilist.org·shvilangel.org 투명성 페이지)로 게시 — 지역별 생성량 추이, 생성 코인과 구매 코인의 비율, 이상 패턴 포착 현황(익명). 물리적으로 불가능한 패턴(동일 코인 이중 사용, 동일 회원 번호의 초과 생성, 지역 탑 100 기준선 추월 등)은 자동 포착과 커뮤니티 신고 양쪽으로 걸린다.
5. **소명 책임 원칙 (이상 생성자의 거래 정지)**: 이상 생성으로 포착된 회원은 **그것이 이상 생성이 아님을 본인이 증명해야** 쉬빌 코인 시스템에서 다시 거래할 수 있다. 절차: 포착 → 해당 회원 번호가 소명 대기 목록에 등재되고 각 지갑에 배포 → 수신 지갑들이 그 회원 번호가 생성한 코인의 수령을 보류 → 회원이 shvilist.org 소명 게시판에 증빙(트레킹 기록·사진·동행 증언 등)을 제출 → 검토단(검증 배지 보유자 중 추첨)이 판정 → 통과 시 목록에서 해제되어 거래 재개. 이것은 거래별 중앙 승인이 아니라, 커뮤니티가 운영하는 예외 처리 절차다. 이미 유통 중인 그 회원의 정상 코인과 타인의 거래는 영향받지 않는다.

이 다섯 가지는 0장의 사상과 충돌하지 않는다. 거래는 여전히 무승인·실시간이며, 검사는 전부 수신 기기의 로컬에서 밀리초 안에 끝난다.

## 5. shvilangel.org 작업 패키지 (WP-2)

기술 스택: Next.js + 동일 모노레포. 다국어: 영어(기본)·히브리어(RTL 필수)·한국어·스페인어.

1. **랜딩**: 비전 한 문단 + 엔젤 지도 + "지갑 다운로드" (지갑을 받으면 지도에 엔젤로 등록된다는 흐름을 첫 화면에서 설명).
2. **엔젤 지도**: 전체 엔젤 마커, 서비스 아이콘 필터(방/소파/마당텐트·인터넷·샤워·식사), 클릭 시 프로필 카드 + "지갑 앱에서 메시지 보내기" 딥링크.
3. **엔젤 등록 플로우**: 지갑 앱 설치 유도 → 앱에서 전화 인증·위치 등록·서비스 입력 → 웹 지도에 자동 반영.
4. **코인 마켓**:
   - 리스팅: 엔젤이 앱에서 수량만 올림. **가격은 정하지 않는다.**
   - 가격 제시: 구매자가 수량·단가 제시(스테이블코인).
   - 승인: 엔젤이 앱 알림에서 승인 → 에스크로 실행: 구매자 USDC 예치 확인 → 코인 이전(서명 체인) → USDC 엔젤 지갑 방출.
   - 서버의 역할은 에스크로 상태 관리뿐, SHV 이전 자체는 두 지갑의 서명으로 완결.
   - 수수료: 마켓 체결 시 2~3%(운영 재원). 생태계 내부 대면 지불은 영구 무료.
5. **투명성 페이지 (커뮤니티 모니터 대시보드)**: 민팅 통계(동기화 데이터 기반 추정치임을 명시), **생성 코인 vs 구매 코인 구분 통계**, 지역별 생성량 추이, 이상 포착·소명 처리 현황(익명), 프로모션 발행 현황, 리저브 공시.

## 6. shvilist.org 작업 패키지 (WP-3)

리스트의 기록·자기 인증 공간. 최소 구성으로 시작:

1. 워커 프로필(선택 공개): 완주 여정, 누적 거리, 엔젤 후기.
2. 여정 인증 페이지: 앱에서 공개 설정한 WalkSegmentProof 요약(거리·걸음 수·날짜 — 위치·경로 없음)을 누구나 열람 — "스스로 기록하고 스스로 인증한다"의 공개적 표현.
3. **코스 등록부 (이 사이트의 중심 기능)**: 기본 코스(쉬빌 이스라엘 + 카미노 등 대표 트레킹 코스)의 GPS 폴리라인 공식 등재·배포. 사용자 코스 제안 페이지 — 제안 코스는 후보 상태로 게시되고, 100명 이상의 완주 기록이 쌓이면 공식 코스로 승격되어 앱에 배포된다. 승격 현황(현재 몇 명 등록)을 공개 표시.
4. 코스 정보(초기엔 쉬빌 이스라엘): 구간·급수·엔젤 밀도.
5. **클레임 게시판 (누락 걸음 구제)**: 2.5절의 절차 구현 — 트레킹 정보·사진 업로드 양식, 커뮤니티 인정 투표, 승인 시 자동 산정·민팅·지갑 전송, 처리 현황 공개. 앱에서도 "어제 걸음이 기록되지 않았나요?" 진입점 제공.
6. **완주 인증 게시판 (격려 코인)**: 2.6절 구현 — 완주 사진·트레킹 데이터 업로드 양식, 요건 충족 시 격려 코인 자동 민팅·송금, 코스별 완주 갤러리, 보상 발행 현황 공개.
7. **검증 트레커 탑 100 리더보드 (지역별)**: 전문 산악인·전문 트레커·포터 등 검증 배지를 받은 인물들의 지역별 상위 100 리스트 — 본인 동의하에 트레킹 거리·생성 코인 총량 공개(위치 없음). 검증 엔진의 개연성 상한 기준선으로 자동 연동되며, 기준선을 추월한 생성자 포착 현황(익명 통계)도 함께 공시. 일반 사용자에게는 명예의 전당이자, 시스템에게는 살아 있는 보안 장치.
8. 앱 다운로드.

## 8. 다니엘 쌤 결정 대기 목록

1. 협약 스테이블코인과 체인 확정 (권고: USDC on Base)
2. 코스 회랑 폭 (제안: 개활지 50m ~ 도심 150m 지형별 차등) 및 엔젤 우회 인정 한도 (제안: 편도 5km)
3. 앱 무결성 증명을 민팅 필수 조건으로 할지 (권고: 필수 — 해킹 차단의 핵심)
4. 니모닉 백업 강제 여부 (권고: 강제 아님, 첫 10 SHV 형성 시 강력 권고)
5. 마켓 수수료율 확정 (제안 2.5%)
6. 파일럿 시작 구간과 초기 엔젤 포인트 좌표 수집 방법
7. 요율 확정 — 일상 걸음 미세 요율(1/1,000 vs 1/10,000), 코스 이탈 감액 요율(제안 1/10), 난이도 계수 상한(제안 ×4.0)
8. 클레임 구제 기준 — 인정 투표 기준 인원(제안 5명), 1인당 클레임 빈도 한도(제안 월 2회)
9. 격려 코인 보상액 — 완주 인증(제안 10 SHV)·구간 인증(제안 3 SHV)과 프로모션 기간·총량

*(M0 코인 코어 구현 중 추가 — 아래는 제안대로 구현되어 있으며 확정 시 파라미터/로직 조정만 하면 됨)*

10. 엔젤 우회 잠정분의 소멸 시점 — 구현: 정산으로 구간이 닫힐 때 지불 대상 엔젤의 우회분만 확정, 나머지(다른 엔젤 지불·수동 정산 포함)는 소멸. 대안: 정산 후에도 일정 기간 잠정 유지
11. 코인 분할(잔돈) 스키마 — 지불 금액을 정확히 맞추기 위해 도입. 구현: 소유자가 자식 금액 전체를 서명 커밋(합계 = 부모 금액), 계보·회원 번호는 뿌리를 상속. 수신 지갑이 로컬 검증 가능
12. 인간 한계 주간 상한 — 구현 기본값: 7일 이동 합 300 SHV (지시서 3장의 "주 300 SHV 물리적 불가능" 예시 준용). 지역·코스별 탑 100 기준선 연동 시 갱신 예정
13. 미세 요율 잔여분 이월 — 0.1 SHV 미만 잔여는 다음 날로 이월 누적(일상 걸음 미세 요율이 실제로 쌓이게 하는 장치). 일일 상한 초과 절사분은 이월하지 않음(상한 이월 금지 유지)
