# 검증 가능한 신뢰 지표 설계 (C안 — 별점 대신 "사실")

> 2026-07-16 다니엘 쌤 "C로 진행" 결정. 별점(주관 점수)은 프라이버시를 지키며
> 위조를 막을 수 없다(별점_프라이버시_결정.md R-1e). 대신 **위조가 어려운 객관적
> 사실**로 신뢰를 표현한다. 헌법 제3조(속도보다 진리)·제9조(관계 비저장)에 부합.

## 1. 사실의 위조 견고성 (코드 조사 결과)

| 지표 | 출처 | 견고성 | 근거 |
|---|---|---|---|
| **커뮤니티 인정 완주** | claims 투표(N명) / certificates | **높음** | 타인 N명이 인정해야 성립 — 혼자 못 만듦 |
| **검증 코인 실적** | walk_proof_stats (지문 sync, H-1) | **높음** | 실제 서명된 코인 지문이 동기화돼야 집계. 부풀리려면 진짜 코인 필요 → 인간한계·이중지불 사후 탐지 대상 |
| **활동 기간** | 회원 증서 issuedAt | **높음** | 가입 시점 서명 — 소급 위조 불가 |
| 게스트북 감사 카드 수 | guestbook (M7-A) | 중간 | 엔젤 자발 공개(M7-B와 같은 한계) — 보조 지표 |
| 리더보드 raw 누적 | `POST /leaderboard/enroll` 자기신고 | **낮음** | totalDistanceM/MintedDshv를 본문으로 자기신고, 운영 verified=0 → 위조 가능 |
| 별점(RATING) | M7-B | 낮음 | 위조 가능(R-1e) — "참고 지표"로만 병기 |

**핵심**: 신뢰의 주 지표를 "위조 치명적인 별점"에서 "위조 어려운 완주·검증실적"으로 옮긴다.

## 2. C 설계 — 무엇을 신뢰 지표로 보여줄 것인가

### 트레커(쉬빌리스트)의 신뢰
- **커뮤니티 인정 완주 수** (claims 투표로 인정된 완주/구간)
- **검증 코인 실적** (walk_proof_stats — "실제 걸어 생성한 검증된 활동량")
- **활동 기간** (첫 걸음/가입 이후)
→ "리뷰 많은 경험 트레커" = "완주·검증실적 많은 트레커" (다니엘 쌤 3번 의도)

### 엔젤의 신뢰
- **게스트북 감사 카드 수** (실제 손님이 서명해 보낸 것 — 보조)
- **접대 활동 기간** (첫 접대 이후)
- (첫 접대 보너스 수령 여부 = 실제 접대 1회 이상의 증거)

### 표시 위치
- 지갑·두 웹의 프로필 카드, **M8 동행 게시판**(게시자 실적 → 자율 팀 선택 기준).
- 별점은 "참고 지표"로 **병기**(B 보조). 리더보드 자기신고는 verified=1만 표시.

## 3. 프라이버시 고려 (신뢰 표시가 새 노출을 만들지 않게)

- 이 지표들은 **개인 실적**일 뿐 "누가 누구와" 관계를 남기지 않는다 → M6 프라이버시 안전.
- 다만 "검증 코인 실적"을 세밀한 액수로 공개하면 개인 재정 노출 → **구간 뱃지**
  (예: 신참/경험/베테랑, 또는 완주 0/1~4/5+)로 표현해 세부 액수는 감춘다.
- 완주·거래 실적은 본인이 공개를 선택(자발) — 강제 공개 아님.

## 4. 구현 계획 (M12 완료 후 착수)

1. **server**: GET /trust?member= — 검증 완주 수(claims APPROVED), walk_proof_stats
   기반 실적 뱃지, 활동 기간, 게스트북 카드 수를 집계해 반환(자연어 없음, 숫자·코드만).
   자기신고 리더보드 raw는 verified만. 회원번호는 조회 파라미터로만(본인 실적 공개 맥락).
2. **wallet**: 내 신뢰 지표 화면 + 상대 조회. 프로필에 뱃지 표시.
3. **web-list/web-angel**: 프로필 카드·동행 게시판에 신뢰 뱃지. i18n 4개 언어.
4. **M8 동행 연동**: 게시자의 완주·검증실적 뱃지 표시 → "마음 맞는 경험자와 팀".
5. 별점(M7-B)은 유지하되 UI에서 "참고 지표"로 격하, 신뢰 뱃지를 상위 노출.

### 확인 필요 (다니엘 쌤)
- 실적 표시를 **뱃지(범위)** 로 할지 **정확 수치**로 할지 (프라이버시 vs 정보량).
  개발팀 제안: 뱃지(완주 수·활동기간 등 위조 어려운 것 위주, 코인 액수는 범위).
  → **결정: 뱃지 채택** (2026-07-17, "C 착수해"). 코인 액수는 구간 뱃지(walkTier)로만,
    완주·인증 수는 정수 그대로(위조 어려운 것은 수치 노출 OK), 활동 기간은 일 단위.

## 5. 폐기된 1차 설계 — "교차 목격"(corroboration)과 그 실패

첫 구현(2026-07-17 오전)은 walkTier를 **교차 목격**으로 게이트했다: `/sync/coins`에
지문을 올린 사람이 생산자와 다르면 그 증명을 실적으로 인정. 다니엘 쌤 지적으로
재검토한 결과 **거의 무의미**함이 드러나 폐기했다.

**왜 실패했나**: `/sync/coins`는 지문(요약 JSON)을 **서명 검증 없이** 받는다(프라이버시상
코인 전체를 받지 않는 설계). 따라서 공격자는 버너 2번째 계정을 하나 만들어
`producer=피해자(=자기 본계정), 금액=350` 같은 **완전 조작 JSON**을 올리면 그만이다 —
실제 코인도, 실제 걷기도, 실제 코인 이전도 필요 없다. 하루 400 dSHV 아래로 여러 날에
나눠 올리면 인간 한계 탐지도 피한다.

**개발팀이 처음에 비용을 과대평가했다**: "2번째 계정 + 실제 코인 이전 + 실제 200km
걷기"라고 적었으나, 진짜 비용은 **전화번호·이메일 하나 추가 등록**뿐이었다. 별점 날조와
사실상 같은 수준이라 C안의 취지("위조 어려운 사실")를 스스로 배신했다. 이 오류를
기록으로 남긴다 (헌법 제3조: 속도보다 진리).

## 6. 확정 설계 — 안 A: 서버가 검증한 코인만 실적 (2026-07-17 다니엘 쌤 "A")

**walkTier는 서버가 `verifyCoin`으로 직접 검증한 걷기 코인만 합산한다.**

- **`walk_verified_credit`** 테이블(신규): `proof_hash` PK · `producer_member` ·
  `total_dshv` · `first_verified_at`. 여기 적재되는 **금액은 제출자 주장값이 아니라
  서명된 증명 안의 일자합**에서만 온다. proofHash PK로 분할 형제·재제출이 이중 계상되지
  않는다.
- **`walk_proof_stats`**(기존, 미검증 지문)는 **초과생성 탐지 전용**으로 되돌렸다.
  신뢰 집계는 이 표를 절대 읽지 않는다 — 탐지는 넓게(가짜까지 받아 한계 초과를 잡는다),
  신뢰는 좁게(검증된 것만).
- **적재 경로 (둘 다 완전 검증됨)**:
  1. `POST /trust/coins` (신규, 제출자 서명): 내가 **보유한** 걷기 코인을 올리면 서버가
     검증해 **그것을 걸어 만든 사람**의 실적으로 적재. 제출자에겐 이득이 없다 —
     "내가 받은 코인이 그 사람의 걸음을 증언한다"(헌법 제7조 선행의 순환).
  2. `POST /spot/deposit` (기존): 예치는 이미 `verifySpotDeposit`로 완전 검증된다.
- **3중 게이트**: ① `verifyCoin` 통과(조작 JSON은 서명이 없어 탈락) ② 제출자가 **현재
  소유자**(남의 코인 데이터 도용 기여 차단) ③ 생산자 ≠ 제출자(자기 크레딧 금지 —
  유통된 코인만 실적).
- **운영 무결성 요구**: `requireIntegrity = !devMode` → 운영에서는 **무결성 증서
  (VERIFIED)를 품은 걷기 코인만** 실적이 된다 (결정 대기 3번 필수화와 동일 기준).

### 남는 위험 (정직화 — 헌법 제3조)
- **루팅 기기의 GPS 위조**: 변조 앱이 만든 걷기 증명은 서명이 유효하므로 서버 검증으로
  걸러낼 수 없다. 이것은 신뢰 뱃지만의 문제가 아니라 **코인 발행 전체가 지는 근본 한계**이며,
  같은 방어(앱 무결성 인증 + 인간 한계 + 계보 서명 + 커뮤니티 소명)가 맡는다.
  즉 **뱃지의 신뢰도 = 코인 발행의 신뢰도**이며, 그 이상을 주장하지 않는다.
- **certificates·guestbook**: 자기 제출/자발 게시라 보조 지표로만 표시(강조 안 함).

## 7. 구현 완료 (2026-07-17, M13)

- **@shvil/shared/trust.ts**: TrustSummary·walkTier 구간(STARTER≥1 / EXPERIENCED≥500
  / VETERAN≥2000 dSHV)·trustDayOf(일 절사). 정확 액수는 타입에 없다(구간만).
- **server**: `GET /trust?member=`(공개) · `GET /trust/me`·`PUT /trust/me`·
  `POST /trust/coins`(본인 서명) · 자발 공개 게이트(trust_disclosures — 미공개·미가입
  동일 응답으로 **존재 오라클 차단**) · `GET /companions`·`GET /angels`에 공개 뱃지 동봉.
- **clients**: 지갑(내 신뢰 지표 화면 + 공개 on/off + 동행 카드 뱃지 + 시작 시 보유
  걷기 코인 검증 기여), web-list(동행 게시판·엔젤 프로필 뱃지), web-angel(엔젤 지도
  뱃지). i18n 4개 언어. 별점은 "참고 지표"로 격하(disclaimer 병기).
- **검증**: shared 246 · server 201 · wallet 92 테스트 통과(총 539), 4개 패키지
  typecheck + 두 Next 앱 production build 통과. ★핵심 회귀 테스트: "조작 지문 6건을
  버너 계정으로 올려도 walkTier가 NONE에 머문다"(폐기된 설계였다면 VETERAN).
