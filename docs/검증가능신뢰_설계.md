# 검증 가능한 신뢰 지표 설계 (C안 — 별점 대신 "사실")

> 2026-07-16 다니엘 쌤 "C로 진행" 결정. 별점(주관 점수)은 프라이버시를 지키며
> 위조를 막을 수 없다(별점_프라이버시_결정.md R-1e). 대신 **위조가 어려운 객관적
> 사실**로 신뢰를 표현한다. 헌법 제3조(속도보다 진리)·제9조(관계 비저장)에 부합.

## 1. 사실의 위조 견고성 (코드 조사 결과)

| 지표 | 출처 | 견고성 | 근거 |
|---|---|---|---|
| **커뮤니티 인정 완주** | claims 투표(N명) / certificates | **높음** | 타인 N명이 인정해야 성립 — 혼자 못 만듦 |
| **검증 코인 실적** | walk_proof_stats (지문 sync, H-1) | **높음** | 실제 서명된 코인 지문이 동기화돼야 집계. 부풀리려면 진짜 코인 필요 → 인간한계·이중지불 사후 탐지 대상 |
| **활동 기간** | 회원 증서 issuedAt | **높음** | 가입 시점 서명 — 소급 위조 불가 |
| 게스트북 감사 카드 수 | guestbook (M7-A) | 중간 | 엔젤 자발 공개(M7-B와 같은 한계) — 보조 지표 |
| 리더보드 raw 누적 | `POST /leaderboard/enroll` 자기신고 | **낮음** | totalDistanceM/MintedDshv를 본문으로 자기신고, 운영 verified=0 → 위조 가능 |
| 별점(RATING) | M7-B | 낮음 | 위조 가능(R-1e) — "참고 지표"로만 병기 |

**핵심**: 신뢰의 주 지표를 "위조 치명적인 별점"에서 "위조 어려운 완주·검증실적"으로 옮긴다.

## 2. C 설계 — 무엇을 신뢰 지표로 보여줄 것인가

### 트레커(쉬빌리스트)의 신뢰
- **커뮤니티 인정 완주 수** (claims 투표로 인정된 완주/구간)
- **검증 코인 실적** (walk_proof_stats — "실제 걸어 생성한 검증된 활동량")
- **활동 기간** (첫 걸음/가입 이후)
→ "리뷰 많은 경험 트레커" = "완주·검증실적 많은 트레커" (다니엘 쌤 3번 의도)

### 엔젤의 신뢰
- **게스트북 감사 카드 수** (실제 손님이 서명해 보낸 것 — 보조)
- **접대 활동 기간** (첫 접대 이후)
- (첫 접대 보너스 수령 여부 = 실제 접대 1회 이상의 증거)

### 표시 위치
- 지갑·두 웹의 프로필 카드, **M8 동행 게시판**(게시자 실적 → 자율 팀 선택 기준).
- 별점은 "참고 지표"로 **병기**(B 보조). 리더보드 자기신고는 verified=1만 표시.

## 3. 프라이버시 고려 (신뢰 표시가 새 노출을 만들지 않게)

- 이 지표들은 **개인 실적**일 뿐 "누가 누구와" 관계를 남기지 않는다 → M6 프라이버시 안전.
- 다만 "검증 코인 실적"을 세밀한 액수로 공개하면 개인 재정 노출 → **구간 뱃지**
  (예: 신참/경험/베테랑, 또는 완주 0/1~4/5+)로 표현해 세부 액수는 감춘다.
- 완주·거래 실적은 본인이 공개를 선택(자발) — 강제 공개 아님.

## 4. 구현 계획 (M12 완료 후 착수)

1. **server**: GET /trust?member= — 검증 완주 수(claims APPROVED), walk_proof_stats
   기반 실적 뱃지, 활동 기간, 게스트북 카드 수를 집계해 반환(자연어 없음, 숫자·코드만).
   자기신고 리더보드 raw는 verified만. 회원번호는 조회 파라미터로만(본인 실적 공개 맥락).
2. **wallet**: 내 신뢰 지표 화면 + 상대 조회. 프로필에 뱃지 표시.
3. **web-list/web-angel**: 프로필 카드·동행 게시판에 신뢰 뱃지. i18n 4개 언어.
4. **M8 동행 연동**: 게시자의 완주·검증실적 뱃지 표시 → "마음 맞는 경험자와 팀".
5. 별점(M7-B)은 유지하되 UI에서 "참고 지표"로 격하, 신뢰 뱃지를 상위 노출.

### 확인 필요 (다니엘 쌤)
- 실적 표시를 **뱃지(범위)** 로 할지 **정확 수치**로 할지 (프라이버시 vs 정보량).
  개발팀 제안: 뱃지(완주 수·활동기간 등 위조 어려운 것 위주, 코인 액수는 범위).
