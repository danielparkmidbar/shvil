# 거래소(쉬빌코인.com)와 헌법 제2조 — 충돌 지점 정리

> 작성: 2026-07-26 · 성격: **판정이 아니라 드러내기.** 결정은 다니엘 쌤이 한다.
> 이 문서는 헌법을 해석하거나 개정하지 않는다. 문언이 무엇을 금지하는지, 코드에
> 이미 무엇이 들어 있는지, 세 가지 서로 다른 행위가 각각 어디에 서는지를 실측해
> 나열한다. 권고 없음. 선택지와 각 선택의 귀결만 적는다.

## 1. 제2조 문언 분해 — 정확히 무엇을 금지하는가

`docs/쉬빌_헌법.md:13-14` 전문:

> ## 제2조 (무투자·무법정화폐)
> 외부 투자를 받지 않는다. 법정화폐를 투입해 시장을 만들지 않는다. 비트코인이
> 투자받아 만들어진 암호화폐가 아니듯, 쉬빌 코인도 마찬가지다. 법정화폐로 시장을
> 왜곡하지 마라. 철저한 절약으로, **스스로 작동하는 실제 가치 기반 코인**으로 자란다.

네 개의 규범 문장으로 나뉜다.

| # | 문언 | 금지·요구되는 것 | 문언이 **말하지 않은** 것 |
|---|---|---|---|
| ① | "외부 투자를 받지 않는다" | 제3자 자본을 받는 행위 | 자본과 **매출**을 구분하지 않는다. 코인 매각 대금이 어느 쪽인지 문언에 없다 |
| ② | "법정화폐를 **투입해** 시장을 **만들지** 않는다" | 법정화폐를 시장 안으로 넣어 없던 시장·값을 있게 하는 행위 | **주어가 생략되어 있다.** 누가 투입하면 안 되는지 명시가 없다 |
| ③ | "법정화폐로 시장을 **왜곡하지** 마라" | 법정화폐로 인한 가격 왜곡 | 규모·임계값이 없다. "얼마부터 왜곡인가"가 없다 |
| ④ | "철저한 절약으로, 스스로 작동하는 … 코인으로 자란다" | 자기 부트스트랩(적극 규범) | 운영비를 어디서 조달하는지 없다 |

**②의 핵심 동사는 「투입」이다.** 투입은 방향을 가진 말이다 — 밖에 있던 법정화폐를
시장 **안으로** 넣는 것. 「교환」이나 「매각」과 같은 말이 아니다. 제2조 어디에도
"코인과 법정화폐를 교환하지 마라"거나 "코인을 팔지 마라"는 문장은 없다.

**②의 주어 공백이 이 문서의 모든 쟁점을 낳는다.** 앞뒤 문장이 "외부 투자를 받지
않는다"(주어=쉬빌)와 "스스로 작동하는"(주어=쉬빌)이므로, 문맥상 생략된 주어는
**쉬빌/창립자**로 읽는 것이 자연스럽다. 그러나 문언은 그렇게 못 박지 않았고,
"누구든 법정화폐를 이 코인 시장에 넣지 마라"로도 읽힌다. **이 두 독법이 (a)를
허용과 금지로 갈라놓는다.**

### 함께 걸리는 다른 조항

- **제1조** (`쉬빌_헌법.md:11`): "이 코인의 목적은 돈을 버는 것이 아니다."
  → 제2조가 **수단**을 규율한다면, 제1조는 **목적**을 규율한다. 거래소가 제2조를
  통과하더라도 "왜 만드는가"가 제1조에 별도로 걸린다.
- **적용지침** (`쉬빌_헌법.md:43`): "「쉬빌_리저브_기획보고서.md」의 '파일럿을
  법정화폐(약 45만 달러)로 조달' 권고는 제2조에 따라 **폐기**한다. 파일럿은 절약,
  자원봉사, 그리고 **코인 생태계 자체의 힘**으로 부트스트랩한다."
  → 이 문장이 (c)의 판단 기준이 된다. "코인 생태계 자체의 힘"에 **코인을 팔아
  현금을 만드는 것**이 포함되는지가 갈림길이다.
- **적용지침** (`쉬빌_헌법.md:45`): "성장·매출·사용자 수를 근거로 헌법 원칙의
  예외를 제안하지 마라." → 개정 논거를 "사업이 되니까"로 세우면 이 문장에 막힌다.
  개정하려면 **헌법 자체의 문언을 바꿔야지, 예외를 만들면 안 된다.**

## 2. 이미 코드에 있는 것 (실측)

### 2-1. 달러 스테이블코인 결제는 **이미 완전히 구현되어 있다**

`server/src/market.ts` (385행) — 리스팅→가격 제시→승인→에스크로 전 과정.

| 실측 사실 | 근거 |
|---|---|
| **판매자는 등록 엔젤만 가능** | `market.ts:85-87` — `only registered angels can list coins` |
| **구매자는 인증된 아무 회원** (엔젤일 필요 없음) | `market.ts:120-138` — 인증만 확인 |
| **리스팅에 가격 필드가 물리적으로 없다** | `market.ts:113` 주석 `// 무정가 — 가격 필드는 존재하지 않는다. 구매자가 제시한다.` |
| 자기 리스팅에 자기가 호가 못 냄 | `market.ts:125-127` |
| 에스크로: USDC 예치 → 코인 이전 서명 → 구매자 확인 → USDC 방출 | `market.ts:184-212`, `271-359` |
| **수수료 2.5%가 방출액에서 차감된다** | `market.ts:197`, `344` (`release = total - fee`), 기본값 `app.ts:725` `feeBps: options.feeBps ?? 250` |
| 체인 어댑터는 아직 **Mock** | `server/src/chain.ts:24` `MockChainAdapter`, `app.ts:175` `options.chain ?? new MockChainAdapter()` |
| 금액 단위 microUSDC | `chain.ts:9` |

| 수수료 총액이 공시된다 | `market.ts:363-384` `/transparency/market` → `collectedFeesUsdcMicro` |

**정리:** 코드는 이미 "SHV를 팔고 달러(USDC)를 받는다"를 한다. 즉 **(a)의 뼈대는
이미 서 있다.** 그리고 그 수수료 2.5%는 **법정화폐 가치로 운영 주체에게 들어온다**
— 방출은 `total - fee`만 나가고 차액은 예치 참조에 남는다(`market.ts:344-345`).

### 2-2. `packages/shared/src/booking.ts` 에는 법정화폐가 **없다**

지시에 언급된 파일이라 전문(216행) 확인함. 예약은 **코인 거래가 아니라 일정 약속**의
E2E 메시지 스키마다(`booking.ts:3-7`). 금액·통화·스테이블코인 필드가 **하나도 없다.**
제2조와 무관하다.

### 2-3. **리저브 발행 경로가 코드에 없다 — (c)의 결정적 사실**

`packages/shared/src/types.ts:115-124`, 코인의 출처(Provenance)는 셋뿐이다:

```
| { kind: 'WALK';  proof: WalkSegmentProof }
| { kind: 'GRANT'; grant: SignedGrant }      // types.ts:101 — ANGEL_BONUS | COMMUNITY_CLAIM | COMMUNITY_REWARD | TREASURE
| { kind: 'SPLIT'; parent: Coin; ... }
```

**GENESIS·FOUNDER_RESERVE 같은 발행 종류는 존재하지 않는다.** 코드 전체 검색에서
"리저브"는 전부 **보물 마이닝의 소각 주소**(`spotTreasure.ts` — 코인을 영구 봉인하는
곳, 발행하는 곳이 아니다)를 가리킨다. 웹 투명성 페이지의 리저브 공시는 플레이스홀더
상태다(`apps/web-angel/src/app/transparency/page.tsx:10,94-95`).

즉 `쉬빌_리저브_기획보고서.md`의 **7,000,000 SHV 제네시스 리저브는 문서상 기획일 뿐
구현되어 있지 않다.** 오늘 기준으로 다니엘 쌤이 "리저브한 내 쉬빌 코인"이라고 할 때
그것은 **직접 걸어서 만든 코인**이거나, 아직 존재하지 않는 코인이다.
→ **이 구분이 (c)의 성격을 통째로 바꾼다. 4-3장 참조.**

## 3. 제2조와의 관계가 정리된 적이 있는가 — 문서 이력

**결론: 부분적으로만. 장터 자체에 대한 논증은 어디에도 없다.**

정리된 적이 있는 것은 다음 두 건뿐이다.

1. **수수료 2.5%** — `docs/결정대기_검토.md:29`
   > "**권고: 2.5% 확정.** 운영 재원 최소 수준. 헌법 제2조(무투자·비영리)와 충돌 없음
   > — 투명성 페이지 공시."

2. **SHV 오프체인 / USDC 전용** — `docs/보안감사_M4.md:9`, `:95`
   > "핵심 사상 준수는 양호하다: SHV 오프체인·USDC 전용(무법정화폐) … 헌법 제2·9조에
   > 부합한다."
   > "마켓 수수료 2.5%는 운영 재원이며 공시되어 제2조와 충돌하지 않는다."

**두 건 모두 "장터를 여는 것 자체가 제2조에 걸리는가"는 묻지 않았다.**
감사 보고서의 논리는 "SHV가 온체인이 아니고 USDC는 마켓 결제 전용이므로 무법정화폐"
인데, 이는 ②(투입 금지)에 대한 답이 아니라 **"SHV 자체는 법정화폐가 아니다"**라는
다른 명제에 대한 답이다. 즉 **제2조 ②를 정면으로 다룬 문서는 현재 레포에 없다.**

USDC on Base 확정(`결정대기_검토.md:17-20`, `쉬빌_작업지시서.md:231`)도 "어느 체인을
쓸 것인가"였지 "법정화폐 시장을 열 것인가"가 아니었다.

## 4. 세 가지를 구분한다 — (a) (b) (c)

세 행위는 제2조에 대해 **서로 다른 위치**에 있다. 하나로 묶어 판단하면 안 된다.

### 4-1. (a) 사용자끼리 코인↔현금을 거래하는 **장터를 제공**한다

*(다니엘 쌤은 현금을 쓰지 않는다. 서버는 에스크로 상태만 관리한다.)*

| 조항 | 걸리는가 | 근거 |
|---|---|---|
| ② 법정화폐 투입해 시장 만들기 | **주어 독법에 달렸다** | 주어=쉬빌 → **안 걸림**(쉬빌의 현금이 0원 들어간다). 주어=누구든 → **걸림**(사용자 현금이 시장을 만든다) |
| ③ 법정화폐로 시장 왜곡 | **안 걸림** | 왜곡의 주체가 쉬빌이 아니다. 가격은 구매자가 제시하고 판매자가 수락한다 |
| ① 외부 투자 | **안 걸림** | 코인 값을 받는 것은 엔젤이지 쉬빌이 아니다 |
| 제1조 (목적) | **부분 접촉** | 수수료 2.5%는 법정화폐 가치의 매출이다. 매출의 **용도**가 운영·인프라로 묶여 공시되면 접촉이 해소된다는 것이 `결정대기_검토.md:29`의 기존 처리다 |
| 제9조 (무승인) | **안 걸림** | 코인 이전은 두 지갑의 서명으로 완결된다(`market.ts:271-359`). 서버는 상태만 전이시킨다 |

**남는 사실:** ②의 주어를 "누구든"으로 읽으면 **이미 구현된 코드와 M3 마일스톤 전체가
헌법 위반 상태다.** 감사 보고서는 그렇게 읽지 않았다(`보안감사_M4.md:9`). 이 독법은
문서로 확정된 적이 없고 **암묵적으로 채택되어 있다.**

**추가 충돌 (제2조와 무관하지만 (a)에 직접 걸린다):**
`docs/쉬빌코인_프로토콜_설계.md:15`

> "코인의 구매력은 권장 가격표로 실물 서비스에 고정(peg)된다. **시세 형성·거래소
> 상장·2차 시장 유통은 설계 목표가 아니며, 오히려 억제 대상이다.**"

"거래소는 쉬빌코인.com이 될 것이다"는 이 문장과 **정면으로 충돌한다.** 제2조를
어떻게 하든 이 문장은 별도로 정리해야 한다.

1. **쉬빌코인.com 개발을 지시하면, 담당 에이전트는 착수 전에 제2조를 읽는다.**

2. **security-auditor는 릴리스 감사에서 제2조를 기준으로 삼는다**
   (`보안감사_M4.md:3` "기준: docs/쉬빌_헌법.md(우선)"). 오늘의 감사 결론은 "충돌
   없음"인데, 그 근거가 "SHV 오프체인·USDC 전용"이라는 **다른 명제**다(3장).
   거래소가 커지면 이 근거는 유지되지 않는다. **감사가 통과와 불통과 사이에서

   11일째 아무도 착수하지 않았다.

4. **`헌법:45`가 개정 논거를 막는다** — "성장·매출·사용자 수를 근거로 헌법 원칙의

**요약: 헌법과 실제 계획이 어긋난 채로 두면, 어긋난 상태 그 자체가 자동으로
집행된다.** 앞으로 나오는 모든 마켓·거래소·리저브 관련 판단이 무작위로 갈리고,
그때마다 다니엘 쌤이 개별 중재를 해야 한다. **어느 초안을 택하든 — 혹은 "개정하지
