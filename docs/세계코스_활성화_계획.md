# 세계 10대 트레일 코스 활성화 계획 (M14)

> 2026-07-22 다니엘 쌤 지시: "세계 10대 코스도 이미 경로를 알고 있으니 코스를 활성화."
> 현재 `WORLD_TRAILS`에서 이스라엘만 LIVE, 나머지 10개는 COMING_SOON이다.

## 1. "LIVE"가 실제로 무엇을 요구하는가

`regions.ts`의 LIVE는 단순한 표시 상태가 아니라 **코인 생성이 열린다**는 뜻이다:

- 걷는 사람의 폰이 그 코스 폴리라인의 **회랑 안**에 있을 때만 기준 요율(1km = 1 SHV)이 붙는다.
  회랑 반폭은 지형별 50m(개활지)~150m(도심)이다 (`DEFAULT_CORRIDOR_HALF_WIDTH_M`).
- 회랑 밖 200m까지는 1/10 감액, 그 밖은 일상 걸음 미세 요율이다.
- LIVE 지역에만 엔젤이 등록할 수 있다 (`PUT /angels/me`가 `liveRegions()`로 막는다).

따라서 **폴리라인 좌표의 정확도가 곧 코인의 정직성**이다. 좌표가 틀리면 둘 중 하나가 된다:

1. 실제 트레일을 걷는 사람이 "코스 밖" 판정을 받아 1/10만 받는다 — 앱이 고장 난 것이다.
2. 직선으로 대충 그으면 회랑이 계곡·도로를 가로질러, **차로 지나가도 코인이 생긴다** — 발행 붕괴.

그러므로 이 작업의 본질은 "상태 플래그를 LIVE로 바꾸는 것"이 아니라 **실측 경로 데이터를
확보하는 것**이다. 좌표를 지어내는 것은 선택지가 아니다 (헌법 제3조).

## 2. 조사 결과 (2026-07-22, OpenStreetMap Overpass API)

### 2-1. 데이터는 실재한다 — 그러나 균일하지 않다

| 트레일 | OSM 관계 | 비고 |
|---|---|---|
| Milford Track (NZ) | ✅ rel 1385121 | 32개 way, **2,068점** (54km) — 공식 DOC 운영 |
| Everest Base Camp (NP) | ✅ 있음 | "Everest Base Camp Trek" |
| John Muir Trail (US) | ✅ 있음 | |
| Torres del Paine (CL) | ❌ **route 관계 없음** | 개별 트랙으로만 매핑 |
| Kilimanjaro (TZ) | ❌ **hiking 관계 없음** | 등정 루트 7종이 따로 매핑 |
| Inca Trail (PE) | ⚠️ **오탐** | 검색이 볼리비아 "Takesi Inca Trail"을 잡았다 — 페루 마추픽추 잉카 트레일이 아니다 |
| Camino / Annapurna / TMB / GR20 | ⏳ 확인 중 | Overpass 속도 제한에 걸림 (재시도 필요) |

### 2-2. 네 가지 실제 문제

**① 데이터 규모.** Milford 54km가 2,068점(약 26m 간격)이다. 10개 트레일 총 연장은
대략 2,000km이므로 **원본 그대로면 7~8만 점**이다. 앱은 오프라인 우선이라 코스를
번들·캐시해야 하는데 그대로는 들어갈 수 없다. **단순화(Douglas–Peucker)가 필수**이며,
허용 오차는 회랑 반폭(50~150m)의 1/3 이하로 잡아야 판정이 왜곡되지 않는다.

**② 이름 검색을 신뢰할 수 없다.** "Inca Trail"이 볼리비아의 다른 트레일을 잡았다.
관계 ID는 **사람이 하나씩 확인**해야 한다. 자동 검색에 맡기면 엉뚱한 대륙의 경로로
코인이 열린다.

**③ 경로 변형(variant) 결정이 필요하다.** 이것은 데이터 문제가 아니라 **제품 결정**이다:
- **Camino de Santiago**: Francés / Portugués / Norte / Primitivo … 여러 갈래. 어느 것?
- **Kilimanjaro**: Marangu / Machame / Lemosho / Rongai … 7개 등정 루트. 어느 것?
- **Annapurna**: 서킷 본선 + 우회로 변형.

**④ 현실 제약 — 걸어서 코인을 만드는 것이 가능한 트레일인가.**
- **Inca Trail(페루)**: 허가제. 면허 가이드 동반 필수, 1일 500명 제한.
- **Milford Track(뉴질랜드)**: 사전 예약제, 편도 4일 고정.
- **Kilimanjaro(탄자니아)**: 법으로 가이드 동반 의무.
이 트레일들은 "자유롭게 걸으며 코인 생성"이라는 0층 전제와 어긋난다. 열더라도
엔젤 생태계(호혜 숙박)가 성립하기 어렵다 — 숙소가 지정 캠프/산장이기 때문이다.

## 3. 단계 계획

### M14-0 — 도구 준비 ✅ (완료)

`packages/shared/scripts/fetchTrailCourses.mjs`:
- **매니페스트 주도**: 사람이 확인한 OSM 관계 ID만 받는다 (이름 자동 검색 금지 — 문제 ②).
- Overpass에서 `out geom` 취득 → 멤버 way **순서 정렬·방향 정합**(끝점 잇기) → 단일 폴리라인.
- **Douglas–Peucker 단순화** (기본 허용 오차 20m — 최소 회랑 50m의 1/2.5).
- 구간(segment) 자동 분류: OSM `sac_scale`·`highway`·고도 태그로 terrain 추정 → 사람 검수.
- 출력: `packages/shared/src/worldCourses.ts` (생성 파일, 직접 수정 금지).
- ODbL 출처·취득일을 파일 헤더에 명기.

### M14-1 — 관계 ID 확정 (사람 작업, 다니엘 쌤 결정 필요)

트레일마다 OSM에서 관계를 열어 **경로가 맞는지 눈으로 확인**하고 ID를 매니페스트에 적는다.
Torres del Paine·Kilimanjaro처럼 관계가 없는 곳은 대안이 필요하다 (개별 way 목록 지정,
또는 GPX 업로드 경로 추가).

### M14-2 — 생성·검수

생성기 실행 → 트레일별로 지도에 겹쳐 **시작·끝·주요 분기점**을 확인. 총 연장이 알려진
거리와 ±10% 안에 드는지 대조(잘못 이어붙인 경로를 잡는 가장 빠른 검사).

### M14-3 — 활성화

`WORLD_TRAILS`의 해당 항목을 `status:'LIVE'` + `courseIds:[...]`로 바꾸고, `GET /courses`
배포에 포함. 웹 지역 선택기·지갑 코스 캐시는 이미 이 카탈로그를 읽으므로 코드 변경이 없다.

## 4. 다니엘 쌤 결정 필요

1. **경로 변형**: Camino는 어느 길(Francés 권장 — 가장 널리 걷는 본선)? Kilimanjaro는
   어느 루트? Annapurna는 서킷 본선만?
2. **허가제 트레일**: Inca Trail·Milford·Kilimanjaro를 열 것인가? (가이드·예약 의무라
   자유 도보 전제와 어긋나고 엔젤 숙박이 성립하기 어렵다.) 개발팀 제안: **1차에서 제외**하고
   자유 도보가 가능한 Camino·TMB·GR20·JMT·Annapurna·EBC부터 연다.
3. **일괄 vs 순차**: 10개를 한 번에 열 것인가, 아니면 데이터 확인이 끝난 것부터 순차로
   열 것인가? 개발팀 제안: **순차** — 하나가 잘못된 좌표로 열리면 그 지역 전체의 코인
   생성이 왜곡되므로, 검수를 마친 것만 LIVE로 올린다.

## 5. 남는 위험 (정직화)

- **OSM 정확도는 트레일마다 다르다.** 잘 매핑된 곳(Milford, JMT)과 성긴 곳이 섞여 있다.
  성긴 구간은 회랑을 넓게(MOUNTAIN 100m) 잡아 흡수하되, 실제로 걸은 사람의 보고로
  보정해야 한다.
- **엔젤 생태계는 데이터로 만들어지지 않는다.** LIVE는 "엔젤이 등록할 수 있다"까지이고,
  실제 호혜 숙박은 그 지역 사람들이 참여해야 생긴다. 이스라엘 밖에서는 아직 없다.
- **난이도 계수**는 자동 분류가 근사치다. 최종 값은 사람이 정한다 (코스 이탈 감액 1/10,
  난이도 상한 ×4.0은 이미 확정 파라미터).
